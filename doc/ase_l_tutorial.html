ASE-L — Analog Simulation Environment

A tutorial for the ASE-L simulation cockpit and its Waveform Viewer. Written for analog designers who know Cadence ADE-L and are new to xschem.

1. What ASE-L is

ASE-L is xschem's analog simulation environment, modeled on Cadence ADE-L. Its purpose is to declutter the schematic: instead of scattering simulator control text on the drawing — .param cards, .lib model includes, analysis statements, .save lines — the whole simulation setup lives in a separate simulation state, stored as its own view of the cell (an ngspice_state view alongside schematic and symbol) in the Library Manager. The schematic stays a pure circuit description; the state view holds design variables, model files, analyses, outputs, simulator options and even the waveform-viewer layout, and you can keep several independent state views per cell (corners, testbench variants) and open, save and reload them like any other view.

2. Quick start: the shipped demo

The repository ships a ready-to-run example: an nfet operating-point measurement in the sky130 workarea.

Prerequisites: the launcher runs the in-tree binary src/xschem, which does not exist in a fresh checkout — build it first with ./configure && make from the repo root (sky130A/README.md covers the workarea itself, not the binary build) — and running a simulation requires ngspice on your PATH.

  1. Launch the sky130 environment from the repo root: 
    ./sky130A/run.sh
    (From any other directory, invoke the script by its actual path, e.g. ../sky130A/run.sh — the script itself is relocatable.) This starts xschem with the Cadence-style configuration; the CIW and Library Manager open.
  2. In the Library Manager, select library sky130_tests, then cell test_nfet_final. The View list shows two views: schematic and ngspice_state1.
  3. Double-click ngspice_state1. The ASE window opens, titled Analog Sim Environment test_nfet_final. It arrives pre-loaded:
    • Design Variables: Vgs = 1.8, Vds = 1.0
    • Analyses: four rows — op, dc, ac, tran — with only op Enable-checked (☑); the other three are unchecked (☐)
    • Outputs: one row named id, expression -i(v1), Save checked
  4. Click N&> (Netlist and Run) in the vertical action strip on the right. The status bar turns orange Status: Running, then green Status: Ready when ngspice finishes.
  5. Look at the Outputs pane: the Value column of the id row now reads 409.7u — the drain current, parsed from the print line -i(v1) = 4.096837e-04 in the simulation log. Open the log with Simulation > Log if you want to see the raw ngspice output.

That is the whole loop: open a state view, press N&>, read results. Everything else in this tutorial refines that loop.

3. Tour of the ASE window

Panes

The window has three panes (labelframes with dark-red titles): Design Variables on the left (full height), Analyses top right, Outputs bottom right. Their table columns are:

PaneColumns
Design VariablesName, Value
Analyses#, Type, Enable, Arguments
OutputsName, Value, Plot, Save, Save Options

Behavior worth knowing:

  • Checkbox cells show ☑ (on) / ☐ (off). Clicking an Enable, Plot or Save cell toggles it directly — no dialog needed.
  • Arguments summarizes each analysis as key=value pairs (dc: source start stop step; ac: points start stop dec; tran: step stop; op: none; extra option keys appended).
  • Outputs Name shows your name if you gave one, otherwise the expression (long expressions truncated with ...). Save Options shows allv or alli automatically when the corresponding Save-All flag covers that row.
  • The Outputs pane's Value column is blank before the first run and fills with engineering-formatted results after a successful run. (The Design Variables pane's Value column is different: it always shows each variable's stored value, e.g. 1.8 for Vgs.)
  • Selection is multi-select within one pane; selecting in a pane clears the other two.
  • The gaps between the panes are dividers you can drag. Over a gap the pointer turns into a double arrow. Drag the one between Analyses and Outputs up to see more output rows; drag the one between Design Variables and the two panes at its right left or right. A drag stops before a pane would lose its title, its column headings or its first row. Resizing the window keeps the proportions, and a window closed and opened again in the same xschem comes back with your split. It is not saved to disk: after a restart the window opens with the default split.
  • Double-click a row: variables → Edit Variable, outputs → Edit Output, analyses → Choose Analyses preselected on that row's type.
  • Right-click any pane for a context menu: Add…, Edit…, Delete. Delete removes the selected rows without confirmation.

Toolbar and status bar

  • Under the menubar sits the temperature entry followed by °C. It commits on Return or focus-out and emits .temp <T> in the simulation deck (default 27). A non-numeric entry is restored and ase: temperature must be numeric is echoed.
  • The bottom status bar reads <win#> | Status: <S> | T=<T> C | Simulator: <sim> | State: <view>. The status segment is orange Status: Running during a run, green Status: Ready on success, red Status: Error on a failed run.
  • The window title carries a trailing  * when the session has unsaved state edits. The window number comes from the shared Cadence-style window counter (CIW=1, LibMgr=2, editors and ASE windows 3+).

Menu overview

Menubar cascades, in order: Launch Session Setup Analyses Variables Outputs Simulation Results Tools. Launch and Tools are disabled placeholders in v1. The rest are covered in the sections below; Results > Annotate exists but its two entries (Operating Point info, DC Node Voltages) are disabled in v1.

4. Setting up a simulation

Design

Setup > Design… opens the Setup Design dialog: Library: Cell: View: type-to-filter comboboxes. The View list is limited to schematic views. This binds the state to the circuit it simulates. Session > Design Window raises (or opens) the editor window holding that design whenever you want to look at the circuit.

Model files

Setup > Model Files… opens the Model Files dialog: a two-column table headed File / Section with a right-click menu (Add…, Edit…, Delete; the Delete key works too). The row editor (Add Model File / Edit Model File) has fields File: and Section: (e.g. section tt); File is required. Every mutation commits immediately — there is no OK/Cancel on the table itself. Each row becomes a .lib <file> <section> line in the deck. File paths may use Tcl variable form, e.g. $::SKYWATER_MODELS/sky130.lib.spice (variables only — no command substitution).

Analyses

Analyses > Choose… (or the OP,TR strip button) opens Choose Analyses: a radiobutton row op dc ac tran, an Enable checkbutton, and per-type quick fields:

TypeQuick fields
op(none)
dcSource: Start: Stop: Step:
acPoints: Start: Stop:
tranStep: Stop:

An enabled analysis must have every quick field filled — otherwise OK refuses with ase: enabled <type> analysis needs a non-empty '<f>'. Switching the type radio discards in-form edits of the previous type. OK edits the first state row of the chosen type. The Options… button opens the Analysis Options (<type>) subdialog — a Name/Value table with Name: Value: entry row plus Add / Delete — for extra analysis keys. Extra keys round-trip through the state file and show in the Arguments column, but are not yet emitted into the deck in v1.

Design variables

The = strip button (or right-click Add… in the Design Variables pane) opens Add Variable with fields Name: and Value:. Empty or duplicate names are rejected with the dialog kept open (ase: variable name must not be empty / ase: variable '<name>' already exists). Variables > Edit… (or double-click a row) opens Edit Variable prefilled, focus on Value. Each variable becomes a .param name=value line in the deck, so reference them in the schematic as parameters (e.g. a source value of Vgs).

Outputs

The --> strip button opens Add Output: Name: (optional), Expression:, checkbuttons Plot and Save, and a From Design… button. Save adds .save <expr> and a print <expr> to the deck (this is what fills the Value column); Plot adds the output to the auto-plot graph in the waveform viewer. Empty expressions are rejected (ase: output expression must not be empty).

Select On Design

Rather than typing node names, pick them on the schematic. Three entry points, differing only in which flags the queued outputs get:

  • Outputs > To Be Saved > Select On Design — save only
  • Outputs > To Be Plotted > Select On Design — save + plot
  • The output editor's From Design… button — uses the dialog's own Plot/Save checkboxes (note: it closes the dialog and discards any typed name/expression; and if both checkboxes are unchecked, Save is forced on — a row that is neither plotted nor saved would do nothing in the deck)

The design window is raised and mouse/ESC are seized on its canvas; the CIW echoes ase: Select On Design — click wires/net labels for voltages, pins for terminal currents, sources for currents; ESC ends. Then:

  • Click a wire or a net label → queues a voltage output v(<net>). A wire is the wire right up to a pin.
  • Click on a pin of a device (a transistor, a resistor, a block) → queues the current into that terminal, i(<instance>:<terminal>), and marks the pin with a green ellipse. See Terminal currents below.
  • Click the body of a voltage source or an ammeter → queues its current i(<inst>).
  • Anything else, such as the body of a transistor → ase: nothing to queue there — click a wire or a net label for a voltage, an instance pin for its terminal current, or a voltage source/ammeter for its current. A click on empty canvas says nothing.

Queued rows appear in the Outputs pane immediately; duplicates are merged (flags ORed). Press ESC to end the mode — bindings are restored, the ellipses on the picked pins are removed and the ASE window is raised.

While the mode is up:

  • The prompt at the bottom of the schematic window reads select outputs on design, and ends with the pin a click would take while the pointer is on one: select outputs on design — pin R1:P (terminal current). It names a pin only while the pointer is in the window the mode is on. If you have a block open in a second window, a click in the window without the prompt is an ordinary editor click.
  • A double click is two picks; the second says already queued. The editor's own double click does not run.
  • A click is one pick even if your hand moves while the button is down: the pick is taken where you pressed, no selection rectangle starts, and what you had selected before entering the mode stays selected.
  • A schematic window you open while the mode is up (for example with Ctrl+N in the Cadence-style key profile) is an ordinary editor window: clicks there select as usual, and ESC there does not end the mode. End the mode with ESC in the window it is on.
  • The mode stays up while you look at another tab. A click on a sheet that is neither this session's design nor a block below it queues nothing and says ase: nothing queued — this window shows neither the session's design … nor a sheet below it; switch to that design's window or tab and click there. A block you opened from the design, in a new window or a new tab, still picks.
  • Closing the schematic window the mode is on ends the mode (ase: the design window the pick mode was on is gone — mode dropped). Pressing a selector in the Calculator ends it too, as ESC does, and entering the mode cancels a Calculator selector that is waiting for its click.

Terminal currents

Click on the pin itself: the small square at the end of the device's lead, or the lead beside it. The click is on the pin when the pointer is within the small on-screen distance that selects a pin in the editor (about a dozen pixels) and never more than 10 schematic units from the pin's point. The square itself is the pin at any zoom; zoomed far in, the lead beyond it is the pin only as far as that on-screen distance reaches. A click on a wire is always the wire's voltage, also right next to a pin, a pixel beside the wire, and at any zoom: on a wire, only the pin's own small square is the terminal. It is the mouse pointer that counts, not the snapped crosshair: if the crosshair sits on the pin while the pointer is on the wire a little further off, you get the wire. The prompt at the bottom of the schematic window names the pin before you click; do not go by the outline the editor draws under the pointer, which on a pin with a wire ending on it is the wire. Options > Enable pin selection does not have to be on.

Where two devices touch, pin on pin with no wire between them, click the lead or the body side of the device you mean. The side of the shared point the pointer is on chooses the device, and the CIW says which pin the click took and which other pin is on that point. Two blocks placed edge to edge work the same way: click on the side of the block you mean, whatever the number of pins on each.

A net label near a pin. The pin of a net label or of a port, on its own, is the net's voltage. Where a label sits directly on a device pin, the device's terminal wins at that point and close to it. A label that is only near a device pin behaves the same way where its text reaches within the pin's range. For the voltage there, click a wire of the net, or the label's text more than 10 units from the pin.

The picked pin is marked. A thin green ellipse, taller than wide, appears round each pin you pick, so you can see what you have chosen. The ellipses go away when you leave the mode with ESC. Key 0 (clear all highlights, in the Cadence-style key profile; Shift+K otherwise) removes them at any time in the window you press it in, and in a window or tab opened from it by descending into a block (or the other way round); click a pin again to get its ellipse back. If you press it while you are in the middle of drawing a wire or of another gesture, it clears only the window you are in; press it again after the gesture for the other one. Only the pins you click are marked: rows that were already in the Outputs table when you entered the mode are not. The green is the colour of drawing layer 16, a light green in the dark colour scheme and a darker one in the light scheme. A pin picked under To Be Plotted gets this same green ellipse; its waveform, plotted after the run, has whatever colour the viewer gives it. Only Direct Plot draws the ellipse in the colour of its trace.

The row that appears in the Outputs pane is the simulator's own name for the current into that pin, i(<instance>:<terminal>). Positive is current flowing into the device. Each pin has its own row, the second pin of a resistor included. A voltage source's own current i(v1) is the current into its first pin, so it is the negative of the current into its second pin, i(v1:n2).

You clickThe row
the drain of a sky130 M1 (netlisted as the subcircuit XM1)i(xm1:d)
pin P of the resistor R1i(r1:n1)
the anode of the diode D1i(d1:a)
pin in of your block x1i(x1:in)
that drain again, picked after descending into the block x1i(x1.xm1:d)
the plus pin of the voltage source V1 (its body is still i(v1))i(v1:n1)

The terminal names are ngspice's: a bare MOSFET has d g s b_tj, a bipolar c b e, a diode a c, and any other plain device is numbered along its netlist line, n1, n2. For a PDK device or a block (anything netlisted as X…) the terminal is the port name on its .subckt line, which is not always the symbol's pin name: pins M, P and B of a sky130 poly resistor come back as r0, r1 and sub. ASE-L looks for that .subckt line in the netlist it last made for the design (while the sheet has not changed since), in the device's own device_model attribute, in the files under Setup > Model Files, and in the model files that netlist names with .lib or .include. So if your models are named on the sheet itself (a .lib line in a code block, the PDK's corner symbol), netlist or run once from ASE-L before picking. Do not add that library to Model Files as well: the deck would then load it twice, and ngspice aborted on that when it was tried with the sky130 library. If ASE-L cannot find the .subckt line it uses the symbol's pin name and says so in the CIW, with what to do about it: netlist the design from ASE-L (or run), or name the model file under Setup > Model Files, then pick again. If it finds more than one .subckt line of that name and their ports differ, it does not guess which one the simulator will use: it says so and asks you to leave one definition.

A port that is named with a number, as vendor op-amp models do (.subckt opa 3 2 7 4 6), works like any other: the row carries the port's number, i(x1:3), and ASE-L writes the port's position into the deck.

An instance array or a bus pin is several currents: the Select Bus Bits dialog opens and you choose which.

To read the current as a number, add a row such as idc(xm1:d) under the Outputs pane's Measures tab (the Saves tab has no Value column). Such a row needs neither box ticked: ASE-L asks the simulator for every terminal a Measures row or an enabled measurement reads.

What the simulator must support. ASE-L writes a line .probe I(<instance>,<pin>) into the deck. An ngspice with terminal-current probes measures any pin this way: every terminal of a PDK transistor, a pin of a block. To check yours, look in the simulation log of such a run for the line ASE-PROBE-VERSION 1. If your schematic already carries the same .probe term in a code block, ASE-L does not write it a second time. The current is in the operating-point, DC, AC and transient results. It is not in noise, transfer-function, pole-zero or sensitivity results, nor in a DC sweep over a design variable. After a run that made only noise, transfer-function, pole-zero or sensitivity analyses, with or without a DC sweep over a design variable beside them, the CIW names the terminal rows that have no value for that reason and says which analyses to enable.

With an older ngspice (the log says ASE-PROBE-VERSION 0) the run still goes ahead. Only pins of devices on the top sheet that are not subcircuits are measured, such as a plain resistor or a source. For every other pin the CIW says so after the run, and what to do: ase: /usr/bin/ngspice, the simulator this run started, cannot save the terminal current i(x1.xm1:d): it saves terminal currents only on top-level devices that are not subcircuit instances. ng_w_stb can — pick it under Setup > Simulators… and run again. The sentence names the program that ran (the file itself when no simulator is picked, the picked entry and its file otherwise) and then the simulators you have registered that can save such a current, with the menu to pick one in. When none of them can it says to register a build that does, or to place ammeter.sym in series and click its body. Once ASE-L has measured the program, which it does at the first run, it says the same before a run starts and when you pick such a pin, and the Simulators window lists terminal currents of subcircuit pins or of devices inside subcircuits among what that program cannot do.

If a run stops converging after you picked a pin. To measure a pin's current the simulator puts a zero-volt source in series with it. On a circuit that only just converges that can be enough to stop a transient that ran before (Timestep too small in the log); an ammeter placed at the same pin does the same. ASE-L then says ase: this run did not converge, and its deck asked for <N> terminal current(s) …. Untick Save and Plot on those rows (or remove a Measures row that reads a pin) and run again to see whether they are the cause. ASE-L says this only when the simulator's log shows a convergence failure, so a healthy run that you stopped yourself is not told it. One case gets no such note: a bench whose only analysis is a transfer function can finish although its operating point failed. If its results look wrong, look in the simulation log for The operating point could not be simulated successfully.

When the click is refused it says so in one line: ase: cannot name the terminal current of <instance> pin <pin> — <reason>; place an ammeter (ammeter.sym) in series. That happens when flat netlisting is on; when you have descended through a block instance that carries a spiceprefix; when the symbol's netlist format does not put that pin on its line exactly once; and for a subcircuit with a format of its own, or a spice_sym_def, whose .subckt line ASE-L cannot find, finds twice with different ports, or finds with too few ports.

A name the simulator cannot take. If the name of the instance or of the port holds a character such as an equals sign, a dollar sign, a quote or a brace, the click queues nothing and says ase: nothing queued for <instance> pin <pin> — its current would be the row '…', and a terminal-current row cannot hold …; rename the instance or the port, or place an ammeter (ammeter.sym) in series. Rename it, or use an ammeter. A block's port whose name ends in a backslash is refused the same way; the line then shows a blank where the backslash is and names a blank as the character. The remedy is the same: rename the port, or use an ammeter.

A typed row. You can type i(x1.xm1:d) yourself. A name holding ;, $, =, ' or a brace is not read as a pin's current; with Save ticked ASE-L refuses that row by name before the run. An expression row that reads a name holding =, ' or a brace does not stop the run: its Value says that name is unknown.

Save All

Outputs > Save All… opens the Save All dialog: checkbuttons Save all voltages (deck: .save all) and Save all terminal currents (deck: .options savecurrents). The Levels: entry is present but disabled in v1.

Simulator options

Simulation > Options… opens Simulation Options, a Name / Value table with row editor Add Simulation Option / Edit Simulation Option (fields Name: Value:). Deck semantics: value 0 — skipped; value 1 — .options <name>; anything else — .options <name>=<value>.

Below the table the sheet carries a Deck preview: every line the next deck will carry for an option, under the place it is written — above the analysis block, inside the analysis block, on the command line, in the run-directory start-up file — and, under not delivered, each option that will not arrive as asked. Under those four places a line that stands four spaces in is a line of the deck, character for character; a place with no line says (nothing). The lines under not delivered are notes about an option, not lines of the deck.

An option stored against one analysis (the Scope box, or Simulator Options… on an analysis form) is written around that analysis and put back after it. Inside the analysis block the preview lists these lines in groups, one per analysis, each under a heading such as TRAN BLOCK, in the order the deck will run the analyses. When device operating-point numbers are saved and another analysis is enabled, the deck runs the operating point behind the other analyses, and its heading says so: OP BLOCK -- runs last in this deck. An s-parameter analysis still runs after it; the heading then names what the operating point runs after (OP BLOCK -- runs after tran in this deck). The one exception is a script that forces the one-line form of the device requests (ase::op_tier_force_set b), which keeps the operating point first. The order is settled by the netlist of the run. Before one has been written in this session it is not settled yet, and neither is it when the netlist on disk is not the one this session wrote last or was written while the operating point was switched off; the groups are then shown operating point first, under one line in parentheses that says what the operating point will run after when device operating-point numbers are saved. An option that cannot be put back after its analysis has a note that names the analyses that run after it. The preview follows the bench while the sheet is open: a new netlist, the Save All dialog and the Analyses pane all repaint it, and it is read again from the netlist on disk each time the sheet gets the keyboard focus.

5. Running

Netlist and Run vs. Run

  • Simulation > Netlist > Recreate regenerates the clean circuit netlist to <rundir>/<cell>.spice (ase: netlist written: <nl>). Simulation > Netlist > Display shows it read-only.
  • Netlist and Run (N&>) re-netlists the design (switching through the Design Window if needed) and runs — the normal button after schematic edits.
  • Run (>) runs on the existing <cell>.spice. Hand-edits to that file survive, and it works with the design window closed. If the netlist artifact is missing you get ase: no netlist artifact: <nl> (run Simulation > Netlist > Recreate first).

The run directory is the state's rundir if set, otherwise the default simulation directory ($USER_CONF_DIR/simulations). ASE renders the full deck to <rundir>/<cell>_ase.spice — circuit netlist, then .lib models, .param variables, .options, .temp, .save lines, and a .control block with the enabled analyses, print statements for saved outputs, and a write <rundir>/<cell>_ase.raw — and executes ngspice -b <deck> in the run directory.

Log window and completion

The log toplevel, titled Simulation Log — <design cell>, live-streams ngspice output during the run. Ctrl-W closes it; Simulation > Log raises it or recreates it from the buffer or <cell>_ase.log. On completion the log is flushed to <cell>_ase.log, results are parsed from <expr> = <float> print lines, and on exit 0 the Outputs Value cells fill, the status goes green, and auto-plot runs; on a nonzero exit the status goes red. The CIW echoes ase: simulation finished (exit <n>), log: <path>.

Stop

Stop (!) kills the running simulation (Unix only — ase: Stop is not available on Windows). With nothing running: ase: no simulation running for this session.

6. The Waveform Viewer

Each ASE session owns at most one waveform viewer — a real xschem editor window repurposed: read-only for its whole life, editor toolbar and bindings removed, its own menubar installed. Title: Waveforms <design cell> (<state view>). Open or raise it with the ~ strip button or Tools > Waveform Viewer (opening it that way adds no traces).

The viewer has a user guide of its own: The ASE Waveform Viewer — strips and traces, cursors, markers, zooming and organising, the complete keyboard and mouse reference, and how to rebind its keys. This section is only the orientation you need to get a plot on screen.

Three ways traces get there

  • Auto-plot: every Outputs row with Plot checked is rebuilt into one dedicated auto graph after each successful run. It is always-replace: the auto graph's traces are cleared and re-added, so it always mirrors the current Plot column. With zero Plot rows no viewer is opened (and an already-open viewer's auto graph is emptied). If the run produced only op results there is nothing to sweep: ase: op results have no sweep — nothing to auto-plot.
  • Direct Plot: Results > Direct Plot (or Ctrl-4 on the schematic) enters a Select-On-Design variant (ase: Direct Plot — click wires/net labels for voltage traces, pins for terminal currents, sources for current traces; ESC plots). Clicks queue trace expressions without touching the session outputs. On ESC the queue is plotted, into the target strip or into one strip per signal depending on the viewer's plot mode. Direct-Plot graphs are never touched by subsequent auto-plots. If no run has produced a raw file yet the traces are recorded and resolve after the next run. A pin's current is the exception: Direct Plot does not change the deck, so it can plot a terminal current only if the last run saved it. Otherwise the click queues nothing and says why, where ASE-L knows: when the last run's simulator cannot save such a current, ase: terminal current 'i(xm1:d)' is not in this session's results: /usr/bin/ngspice, the simulator of the last run, cannot save it. ng_w_stb can — pick it under Setup > Simulators… and run again. (and once you have picked it, … ng_w_stb is picked now — run again.); when the last run gave another reason, that reason; when the row is already set to be saved, … it is set to be saved, and these results are from before that — run again. — or, if the simulator this session starts is already known to be unable to save it, that, and which registered one can; and when nothing is known about it, ase: terminal current 'i(xm1:d)' is not in this session's results — pick it under Outputs > To Be Saved > Select On Design and run again. On the pin of a voltage source or an ammeter whose own pin current was not saved, the click plots the source's current instead, exactly as a click on its body does. On the source's second pin that trace is the negative of the pin's own current, and the CIW says so (ase: V1 pin m — the trace is the source's own current 'i(v1)', which is the current into its first pin, so the current into V1 pin m is the negative of that trace …); on a control pin of a controlled source the CIW says the trace is not that pin's current, and to place an ammeter for it; where another device's pin is on the same point, the CIW names it and says the click took the source's current. If you close the schematic window Direct Plot is on instead of pressing ESC, the queued traces are not plotted: the CIW says how many, and the colours their clicks left on the schematic stay until you clear the highlights. A pin whose current is plotted gets an ellipse in the colour of its trace. Like the colours on picked wires it stays after ESC, until you clear the highlights (key 0 in the Cadence-style key profile). If a later run replaces the viewer's traces, the ellipse still has the old colour: clear the highlights and pick again.
  • Plot Difference: Alt-Shift-D on the schematic (Cadence-style key profile only; there is no menu entry) plots the difference of two nets. The bottom status line asks for the first net (Plot Difference (transient): click the first net; ESC cancels), then for the second (Plot Difference (transient): click second net (second minus first); first net inp; ESC cancels); at the second click the trace second minus first is plotted and the mode is over, with no ESC. ESC before that cancels. A net is a wire or a net label; anything else, a bus, the first net again or a net the run did not save plots nothing and says what to click instead, then what was clicked (Plot Difference (transient): click a wire or a net label for the first net (R1 is not a net)). Where the status line has no room for a whole sentence it shows the beginning of it, which is why each begins with what to click; the CIW has every sentence whole. You may descend, or return, between the two clicks. The key reads the transient of the session's results, whatever the viewer is showing. If the results hold no transient and exactly one of AC and a DC sweep, that one is read and the CIW says so; if they hold both, the key plots nothing and names them. To read AC or the DC sweep from a key of its own, uncomment one of the two example lines under the Alt-Shift-D line of cadence_style_rc: the word after the command (tran, ac, dc) is the analysis. For AC the trace is the magnitude of the difference of the two complex voltages. The trace's legend is the difference written out with its two nets, v(<second>)-v(<first>) (for AC inside mag()), each net spelled as a Direct Plot of it is. Nothing is added to the session outputs. The trace is an expression trace like one plotted from the Calculator, and it keeps drawing when the results are loaded again by a Direct Plot or another Plot Difference. Across a re-run it depends on the plot destination (the drop-down at the right end of the ASE-L status bar), because a finished run plots the ticked Outputs rows, as ~ does. Under Replace, the default, that plot empties the target subwindow first, and a difference standing there goes with the other traces; one u in the viewer brings them back, on the new run's numbers. Under Append, or with the difference in another subwindow or tab, it stays and shows the new run's numbers. If the new result lacks one of the two nets, or the viewer is switched to another analysis than the one the difference was read from, the trace stays in its strip, empty, and the CIW says which trace and what to do (wviewer: trace 'v(b)-v(a)' is empty: v(b) is not in the results the viewer now shows (the transient analysis of top_ase.raw); save it in ASE-L (Outputs > To Be Saved) and run again, and the trace draws again).

Each run overwrites <cell>_ase.raw in place and re-attaches it, so auto-plot and Direct Plot graphs simply show fresh data. So do expression traces (a Plot Difference, a Calculator plot, a multi-token RPN expression added through Graph > Add Trace…): the viewer evaluates each again on the new data. One that names a signal the new result does not hold stays in its strip, empty, and the CIW says which signal to save. Under the Replace destination the run's own plot empties the target subwindow first, as it always did, whatever kind of trace stands there.

Viewer menus, at a glance

  • File: Close (Ctrl+W)
  • View: Fit, Zoom In, Zoom Out, Redraw
  • Graph: Add Graph, Add Trace…, Delete…, Axes…, Clear All, Delete All Markers, Delete Empty Strips, Split Strip, and the checkbuttons Shared X Axis and Grid
  • Cursors: checkbuttons Cursor A, Cursor B, Readout
  • Options: Plot Mode (single / multi; Ctrl-Shift-M in the viewer)

Graphs stack vertically; trace colors auto-cycle through the layer palette. Every zoom and pan command acts on the graph data range, never on the window: the graph always fills the viewer, so a canvas zoom would only shrink the plot. The rest — what each entry does, the dialogs, the gestures and the keys — is in the Waveform Viewer guide.

7. Worked example: a DC sweep

Turn the quick-start op point into an Id–Vgs curve.

  1. In the demo session, open Choose Analyses (the OP,TR button). Select the dc radiobutton, check Enable, and fill the quick fields: Source: V2, Start: 0, Stop: 1.8, Step: 0.01 (V2 is the gate source in this testbench). Click OK. The Analyses pane now shows the dc row enabled with Arguments source=V2 start=0 stop=1.8 step=0.01.
  2. In the Outputs pane, click the id row's Plot cell so it shows ☑ (Save stays checked).
  3. Click N&>. When the status returns to green, the Waveform Viewer opens with the auto graph: id versus the swept gate voltage. (Behind the scenes the output -i(v1) was mapped to the RPN trace i(v1) -1 *.)
  4. Enable Cursors > Cursor A. The readout bar appears; drag the cursor along the curve and read the interpolated drain current at each gate voltage, engineering-formatted (e.g. A: x=905m   ...).
  5. Optional polish: Graph > Axes... and check Log Y to see the subthreshold slope; View > Fit to reframe.

8. Saving and reloading sessions

Save State

Session > Save State always opens the Save State form — a Save-As with Library: (type-to-filter combobox) and Cell: / View: entries prefilled with the session's own library/cell/view, so a bare OK is a plain save. Rules:

  • Saving to a different existing view overwrites it without confirmation.
  • Saving to a nonexistent view auto-creates it (the cell must already exist).
  • A session opened read-only (or whose file is unwritable) overwriting its own view gets a confirm titled Overwrite State: The state <l>/<c>/<v> was opened read-only. Overwrite it?
  • Success echoes ase: state saved to <l>/<c>/<v>.

The waveform-viewer snapshot (open flag, shared-x, raw file reference, and the full graph/trace layout) is folded into the state before every save. Viewer layout edits alone never mark the session dirty — they are captured at save time. A state saved with its viewer open relaunches the viewer when that state is next opened fresh (or imported via Load State). An empty rawfile means "the current run's raw"; a hand-edited path (absolute, or relative to the rundir) is honored at restore.

Load State

Session > Load State opens the Load State browser: three list columns headed Library Cell View, the View column filtered to simulation-state views. If the session is dirty, a confirm titled Load State asks Discard unsaved edits of this session and load <lib>/<cell>/<view>?. Loading is a content import into the current session: the window, its state-view path and its number are untouched — you pulled another state's contents in, and the dirty marker appears if the imported content differs from what is on disk for this session's own view.

Creating a state view from scratch

In the Library Manager, use the New View dialog (titled New view in <cell>): enter a View name: and pick Editor type ngspice_state1 from the Editor type: combobox (schematic symbol ngspice_state1). The view is seeded with a complete default state pointing at the cell's schematic view — never an empty file. (Save State to a nonexistent view does the same implicitly.) Opening any state view: double-click it in the Library Manager, or use the read-only variant Open (read-only) — note that in v1 the read-only flag only adds the Save-As overwrite confirmation; it does not block edits in the session window.

The state file

The state lives at <libpath>/<cell>/<view>/<cell>.state — a flat, human-readable Tcl dict, one key per line, in canonical order (version simulator design rundir temperature models variables analyses outputs save_all_v save_all_i options includes viewer). It round-trips byte-stable and diffs cleanly, so state views version well under git.

9. Tips & reference

Dialogs

  • All ASE dialogs are modeless. Return in an entry is OK; ESC is Cancel. The ASE session window and the log window are deliberately not ESC-bound (ESC there does nothing).
  • Delete (the X button or context-menu Delete) asks no confirmation. So does closing the session: unsaved edits are discarded with a CIW notice, and the log window and waveform viewer close with it.

Engineering notation

Value columns and the viewer readout format numbers in engineering notation with SPICE suffixes (f p n u m k Meg G T), about four significant digits: 4.096837e-04 displays as 409.7u. This is display-only — state files and dialog fields carry the raw values. To get scientific notation back, uncomment the prepared line in your rc file (sky130A/cadence_style_rc, gf180mcuD/cadence_style_rc or src/cadence_style_rc):

# set ase_eng_notation 0

Files in the run directory

FileWhat it is
<cell>.spiceclean circuit netlist (Netlist > Recreate); hand-editable, used by Run
<cell>_ase.spicefull simulation deck rendered by ASE for each run
<cell>_ase.rawwaveform data (overwritten in place each run)
<cell>_ase.logngspice output; source of the parsed result values

Scripting

Open a state from Tcl with ase::open_state <lib> <cell> <view> ?ro? — returns 1/0, never throws; re-opening an already-open state raises the existing window.

v1 limitations (honest list)

  • Launch and Tools menus are disabled placeholders; Results > Annotate entries (Operating Point info, DC Node Voltages) are disabled.
  • op-only results have no sweep and plot nothing (auto-plot and Direct Plot both report it).
  • A terminal current picked on a pin needs an ngspice with terminal-current probes; an older one measures only top-level devices that are not subcircuits and reports the rest after the run.
  • The ellipse on a picked pin is not drawn in SVG, PostScript or PDF exports.
  • The Calculator's current selectors (it, if, idc, is) take a device pin too, but insert its current only if the loaded result already holds it: the Calculator cannot ask the simulator for a current. To get it there, pick the pin under Outputs > To Be Plotted > Select On Design and run again: the Calculator reads what the waveform viewer has loaded, and a run loads its results there when it plots something. In a session with only an operating point the Calculator may not see a newly saved pin.
  • In the Calculator, after a single click has inserted a net or a current, a second quick click goes to the editor: a double click there opens the editor's property dialog, or selects the net under the Cadence-style profile.
  • The pick mode of the Results Display Window (keys 1 to 4) can still be up together with Select On Design or a Calculator selector. The status bar of the schematic window then shows the prompt of the mode you entered last, and that is the mode your clicks go to. Leave them with ESC on the schematic, once for each mode. ESC pressed in the Results Display Window ends that window's mode only, whichever mode you entered last: the other mode stays up, with its prompt on the status bar, and ESC on the schematic leaves it. That ESC in the Results Display Window can move the keyboard to the schematic; click in the Results Display Window again before you use the keyboard there. If you press a Calculator selector again, or close the Calculator, while the Results Display Window's mode is on top of it, that mode stays up: press ESC on the schematic to leave it. The same holds when you close the ASE-L window with that mode on top of Select On Design. After such a selector press the keyboard is on the schematic, so click in the Calculator's buffer before you type there again.
  • If your design is in a tab other than the first and another xschem window is open (the waveform viewer, a block in its own window), the first tab can come to the front when you enter Select On Design, press a Calculator selector or move the pointer back from the other window. Click your design's tab and go on. Select On Design is still up, and a click on the wrong sheet queues nothing and says so. A Calculator selector is cancelled by a click on the wrong sheet: press it again after you have clicked your design's tab.
  • Direct Plot cannot plot a terminal current the last run did not save (on the pin of a voltage source or an ammeter it plots the source's own current instead, which on the source's second pin is the negative of the pin's own).
  • A terminal row is not checked before the run: a mistyped one is reported after it.
  • The pin pick is refused under flat netlisting, below a block instance that carries a spiceprefix, and for a symbol whose netlist format does not put the pin on its line exactly once.
  • Extra analysis keys from Analysis Options are stored and displayed but not yet emitted into the deck.
  • The Levels: entry in Save All is disabled.
  • Read-only open gates only the Save-As overwrite confirmation; it does not block edits.
  • Stop is unavailable on Windows.
  • No digital/mixed-signal lanes; the simulator is ngspice.
