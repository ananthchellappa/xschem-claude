ASE-L — Analog Simulation Environment

A tutorial for the ASE-L simulation cockpit and its Waveform Viewer. Written for analog designers who know Cadence ADE-L and are new to xschem.

1. What ASE-L is

ASE-L is xschem's analog simulation environment, modeled on Cadence ADE-L. Its purpose is to declutter the schematic: instead of scattering simulator control text on the drawing — .param cards, .lib model includes, analysis statements, .save lines — the whole simulation setup lives in a separate simulation state, stored as its own view of the cell (an ngspice_state view alongside schematic and symbol) in the Library Manager. The schematic stays a pure circuit description; the state view holds design variables, model files, analyses, outputs, simulator options and even the waveform-viewer layout, and you can keep several independent state views per cell (corners, testbench variants) and open, save and reload them like any other view.

2. Quick start: the shipped demo

The repository ships a ready-to-run example: an nfet operating-point measurement in the sky130 workarea.

Prerequisites: the launcher runs the in-tree binary src/xschem, which does not exist in a fresh checkout — build it first with ./configure && make from the repo root (sky130A/README.md covers the workarea itself, not the binary build) — and running a simulation requires ngspice on your PATH.

  1. Launch the sky130 environment from the repo root: 
    ./sky130A/run.sh
    (From any other directory, invoke the script by its actual path, e.g. ../sky130A/run.sh — the script itself is relocatable.) This starts xschem with the Cadence-style configuration; the CIW and Library Manager open.
  2. In the Library Manager, select library sky130_tests, then cell test_nfet_final. The View list shows two views: schematic and ngspice_state1.
  3. Double-click ngspice_state1. The ASE window opens, titled Analog Sim Environment test_nfet_final. It arrives pre-loaded:
    • Design Variables: Vgs = 1.8, Vds = 1.0
    • Analyses: four rows — op, dc, ac, tran — with only op Enable-checked (☑); the other three are unchecked (☐)
    • Outputs: one row named id, expression -i(v1), Save checked
  4. Click N&> (Netlist and Run) in the vertical action strip on the right. The status bar turns orange Status: Running, then green Status: Ready when ngspice finishes.
  5. Look at the Outputs pane: the Value column of the id row now reads 409.7u — the drain current, parsed from the print line -i(v1) = 4.096837e-04 in the simulation log. Open the log with Simulation > Log if you want to see the raw ngspice output.

That is the whole loop: open a state view, press N&>, read results. Everything else in this tutorial refines that loop.

3. Tour of the ASE window

Panes

The window has three panes (labelframes with dark-red titles): Design Variables on the left (full height), Analyses top right, Outputs bottom right. Their table columns are:

PaneColumns
Design VariablesName, Value
Analyses#, Type, Enable, Arguments
OutputsName, Value, Plot, Save, Save Options

Behavior worth knowing:

  • Checkbox cells show ☑ (on) / ☐ (off). Clicking an Enable, Plot or Save cell toggles it directly — no dialog needed.
  • Arguments summarizes each analysis as key=value pairs (dc: source start stop step; ac: points start stop dec; tran: step stop; op: none; extra option keys appended).
  • Outputs Name shows your name if you gave one, otherwise the expression (long expressions truncated with ...). Save Options shows allv or alli automatically when the corresponding Save-All flag covers that row.
  • The Outputs pane's Value column is blank before the first run and fills with engineering-formatted results after a successful run. (The Design Variables pane's Value column is different: it always shows each variable's stored value, e.g. 1.8 for Vgs.)
  • Selection is multi-select within one pane; selecting in a pane clears the other two.
  • Double-click a row: variables → Edit Variable, outputs → Edit Output, analyses → Choose Analyses preselected on that row's type.
  • Right-click any pane for a context menu: Add…, Edit…, Delete. Delete removes the selected rows without confirmation.

Action strip

The vertical button strip on the right edge, top to bottom:

ButtonAction
OP,TRChoose Analyses dialog
=Add Variable dialog
-->Add Output editor
XDelete the current pane selection
N&>Netlist and Run
>Run (existing netlist)
!Stop
~Raise/open the session's waveform viewer

Toolbar and status bar

  • Under the menubar sits the temperature entry followed by °C. It commits on Return or focus-out and emits .temp <T> in the simulation deck (default 27). A non-numeric entry is restored and ase: temperature must be numeric is echoed.
  • The bottom status bar reads <win#> | Status: <S> | T=<T> C | Simulator: <sim> | State: <view>. The status segment is orange Status: Running during a run, green Status: Ready on success, red Status: Error on a failed run.
  • The window title carries a trailing  * when the session has unsaved state edits. The window number comes from the shared Cadence-style window counter (CIW=1, LibMgr=2, editors and ASE windows 3+).

Menu overview

Menubar cascades, in order: Launch Session Setup Analyses Variables Outputs Simulation Results Tools. Launch and Tools are disabled placeholders in v1. The rest are covered in the sections below; Results > Annotate exists but its two entries (Operating Point info, DC Node Voltages) are disabled in v1.

4. Setting up a simulation

Design

Setup > Design… opens the Setup Design dialog: Library: Cell: View: type-to-filter comboboxes. The View list is limited to schematic views. This binds the state to the circuit it simulates. Session > Design Window raises (or opens) the editor window holding that design whenever you want to look at the circuit.

Model files

Setup > Model Files… opens the Model Files dialog: a two-column table headed File / Section with a right-click menu (Add…, Edit…, Delete; the Delete key works too). The row editor (Add Model File / Edit Model File) has fields File: and Section: (e.g. section tt); File is required. Every mutation commits immediately — there is no OK/Cancel on the table itself. Each row becomes a .lib <file> <section> line in the deck. File paths may use Tcl variable form, e.g. $::SKYWATER_MODELS/sky130.lib.spice (variables only — no command substitution).

Analyses

Analyses > Choose… (or the OP,TR strip button) opens Choose Analyses: a radiobutton row op dc ac tran, an Enable checkbutton, and per-type quick fields:

TypeQuick fields
op(none)
dcSource: Start: Stop: Step:
acPoints: Start: Stop:
tranStep: Stop:

An enabled analysis must have every quick field filled — otherwise OK refuses with ase: enabled <type> analysis needs a non-empty '<f>'. Switching the type radio discards in-form edits of the previous type. OK edits the first state row of the chosen type. The Options… button opens the Analysis Options (<type>) subdialog — a Name/Value table with Name: Value: entry row plus Add / Delete — for extra analysis keys. Extra keys round-trip through the state file and show in the Arguments column, but are not yet emitted into the deck in v1.

Design variables

The = strip button (or right-click Add… in the Design Variables pane) opens Add Variable with fields Name: and Value:. Empty or duplicate names are rejected with the dialog kept open (ase: variable name must not be empty / ase: variable '<name>' already exists). Variables > Edit… (or double-click a row) opens Edit Variable prefilled, focus on Value. Each variable becomes a .param name=value line in the deck, so reference them in the schematic as parameters (e.g. a source value of Vgs).

Outputs

The --> strip button opens Add Output: Name: (optional), Expression:, checkbuttons Plot and Save, and a From Design… button. Save adds .save <expr> and a print <expr> to the deck (this is what fills the Value column); Plot adds the output to the auto-plot graph in the waveform viewer. Empty expressions are rejected (ase: output expression must not be empty).

Select On Design

Rather than typing node names, pick them on the schematic. Three entry points, differing only in which flags the queued outputs get:

  • Outputs > To Be Saved > Select On Design — save only
  • Outputs > To Be Plotted > Select On Design — save + plot
  • The output editor's From Design… button — uses the dialog's own Plot/Save checkboxes (note: it closes the dialog and discards any typed name/expression; and if both checkboxes are unchecked, Save is forced on — a row that is neither plotted nor saved would do nothing in the deck)

The design window is raised and mouse/ESC are seized on its canvas; the CIW echoes ase: Select On Design — click wires/net labels for voltages, sources for currents; ESC ends. Then:

  • Click a wire, net label or labeled pin → queues a voltage output v(<net>).
  • Click a voltage source or ammeter instance → queues a current output i(<inst>).
  • Anything else → ase: v1 queues source currents only — click a wire, a net label or a voltage source/ammeter. (Per-terminal currents of arbitrary devices are deferred in v1.)

Queued rows appear in the Outputs pane immediately; duplicates are merged (flags ORed). Press ESC to end the mode — bindings are restored and the ASE window is raised.

Save All

Outputs > Save All… opens the Save All dialog: checkbuttons Save all voltages (deck: .save all) and Save all terminal currents (deck: .options savecurrents). The Levels: entry is present but disabled in v1.

Simulator options

Simulation > Options… opens Simulation Options, a Name / Value table with row editor Add Simulation Option / Edit Simulation Option (fields Name: Value:). Deck semantics: value 0 — skipped; value 1 — .options <name>; anything else — .options <name>=<value>.

5. Running

Netlist and Run vs. Run

  • Simulation > Netlist > Recreate regenerates the clean circuit netlist to <rundir>/<cell>.spice (ase: netlist written: <nl>). Simulation > Netlist > Display shows it read-only.
  • Netlist and Run (N&>) re-netlists the design (switching through the Design Window if needed) and runs — the normal button after schematic edits.
  • Run (>) runs on the existing <cell>.spice. Hand-edits to that file survive, and it works with the design window closed. If the netlist artifact is missing you get ase: no netlist artifact: <nl> (run Simulation > Netlist > Recreate first).

The run directory is the state's rundir if set, otherwise the default simulation directory ($USER_CONF_DIR/simulations). ASE renders the full deck to <rundir>/<cell>_ase.spice — circuit netlist, then .lib models, .param variables, .options, .temp, .save lines, and a .control block with the enabled analyses, print statements for saved outputs, and a write <rundir>/<cell>_ase.raw — and executes ngspice -b <deck> in the run directory.

Log window and completion

The log toplevel, titled Simulation Log — <design cell>, live-streams ngspice output during the run. Ctrl-W closes it; Simulation > Log raises it or recreates it from the buffer or <cell>_ase.log. On completion the log is flushed to <cell>_ase.log, results are parsed from <expr> = <float> print lines, and on exit 0 the Outputs Value cells fill, the status goes green, and auto-plot runs; on a nonzero exit the status goes red. The CIW echoes ase: simulation finished (exit <n>), log: <path>.

Stop

Stop (!) kills the running simulation (Unix only — ase: Stop is not available on Windows). With nothing running: ase: no simulation running for this session.

6. The Waveform Viewer

Each ASE session owns at most one waveform viewer — a real xschem editor window repurposed: read-only for its whole life, editor toolbar and bindings removed, its own menubar installed. Title: Waveforms <design cell> (<state view>). Open or raise it with the ~ strip button or Tools > Waveform Viewer (opening it that way adds no traces).

The viewer has a user guide of its own: The ASE Waveform Viewer — strips and traces, cursors, markers, zooming and organising, the complete keyboard and mouse reference, and how to rebind its keys. This section is only the orientation you need to get a plot on screen.

Two ways traces get there

  • Auto-plot: every Outputs row with Plot checked is rebuilt into one dedicated auto graph after each successful run. It is always-replace: the auto graph's traces are cleared and re-added, so it always mirrors the current Plot column. With zero Plot rows no viewer is opened (and an already-open viewer's auto graph is emptied). If the run produced only op results there is nothing to sweep: ase: op results have no sweep — nothing to auto-plot.
  • Direct Plot: Results > Direct Plot (or Ctrl-4 on the schematic) enters a Select-On-Design variant (ase: Direct Plot — click wires/net labels for voltage traces, sources for current traces; ESC plots). Clicks queue trace expressions without touching the session outputs. On ESC the queue is plotted, into the target strip or into one strip per signal depending on the viewer's plot mode. Direct-Plot graphs are never touched by subsequent auto-plots. If no run has produced a raw file yet the traces are recorded and resolve after the next run.

Each run overwrites <cell>_ase.raw in place and re-attaches it, so auto-plot and Direct Plot graphs simply show fresh data. One exception: expression traces you added manually through Graph > Add Trace… (multi-token RPN expressions) lose their computed vector on the re-attach and draw empty after the next run — re-add the trace, or save and reload the state, to re-materialize them.

Viewer menus, at a glance

  • File: Close (Ctrl+W)
  • View: Fit, Zoom In, Zoom Out, Redraw
  • Graph: Add Graph, Add Trace…, Delete…, Axes…, Clear All, Delete All Markers, Delete Empty Strips, Split Strip, and the checkbuttons Shared X Axis and Grid
  • Cursors: checkbuttons Cursor A, Cursor B, Readout
  • Options: Plot Mode (single / multi)

Graphs stack vertically; trace colors auto-cycle through the layer palette. Every zoom and pan command acts on the graph data range, never on the window: the graph always fills the viewer, so a canvas zoom would only shrink the plot. The rest — what each entry does, the dialogs, the gestures and the keys — is in the Waveform Viewer guide.

7. Worked example: a DC sweep

Turn the quick-start op point into an Id–Vgs curve.

  1. In the demo session, open Choose Analyses (the OP,TR button). Select the dc radiobutton, check Enable, and fill the quick fields: Source: V2, Start: 0, Stop: 1.8, Step: 0.01 (V2 is the gate source in this testbench). Click OK. The Analyses pane now shows the dc row enabled with Arguments source=V2 start=0 stop=1.8 step=0.01.
  2. In the Outputs pane, click the id row's Plot cell so it shows ☑ (Save stays checked).
  3. Click N&>. When the status returns to green, the Waveform Viewer opens with the auto graph: id versus the swept gate voltage. (Behind the scenes the output -i(v1) was mapped to the RPN trace i(v1) -1 *.)
  4. Enable Cursors > Cursor A. The readout bar appears; drag the cursor along the curve and read the interpolated drain current at each gate voltage, engineering-formatted (e.g. A: x=905m   ...).
  5. Optional polish: Graph > Axes... and check Log Y to see the subthreshold slope; View > Fit to reframe.

8. Saving and reloading sessions

Save State

Session > Save State always opens the Save State form — a Save-As with Library: (type-to-filter combobox) and Cell: / View: entries prefilled with the session's own library/cell/view, so a bare OK is a plain save. Rules:

  • Saving to a different existing view overwrites it without confirmation.
  • Saving to a nonexistent view auto-creates it (the cell must already exist).
  • A session opened read-only (or whose file is unwritable) overwriting its own view gets a confirm titled Overwrite State: The state <l>/<c>/<v> was opened read-only. Overwrite it?
  • Success echoes ase: state saved to <l>/<c>/<v>.

The waveform-viewer snapshot (open flag, shared-x, raw file reference, and the full graph/trace layout) is folded into the state before every save. Viewer layout edits alone never mark the session dirty — they are captured at save time. A state saved with its viewer open relaunches the viewer when that state is next opened fresh (or imported via Load State). An empty rawfile means "the current run's raw"; a hand-edited path (absolute, or relative to the rundir) is honored at restore.

Load State

Session > Load State opens the Load State browser: three list columns headed Library Cell View, the View column filtered to simulation-state views. If the session is dirty, a confirm titled Load State asks Discard unsaved edits of this session and load <lib>/<cell>/<view>?. Loading is a content import into the current session: the window, its state-view path and its number are untouched — you pulled another state's contents in, and the dirty marker appears if the imported content differs from what is on disk for this session's own view.

Creating a state view from scratch

In the Library Manager, use the New View dialog (titled New view in <cell>): enter a View name: and pick Editor type ngspice_state1 from the Editor type: combobox (schematic symbol ngspice_state1). The view is seeded with a complete default state pointing at the cell's schematic view — never an empty file. (Save State to a nonexistent view does the same implicitly.) Opening any state view: double-click it in the Library Manager, or use the read-only variant Open (read-only) — note that in v1 the read-only flag only adds the Save-As overwrite confirmation; it does not block edits in the session window.

The state file

The state lives at <libpath>/<cell>/<view>/<cell>.state — a flat, human-readable Tcl dict, one key per line, in canonical order (version simulator design rundir temperature models variables analyses outputs save_all_v save_all_i options includes viewer). It round-trips byte-stable and diffs cleanly, so state views version well under git.

9. Tips & reference

Dialogs

  • All ASE dialogs are modeless. Return in an entry is OK; ESC is Cancel. The ASE session window and the log window are deliberately not ESC-bound (ESC there does nothing).
  • Delete (the X button or context-menu Delete) asks no confirmation. So does closing the session: unsaved edits are discarded with a CIW notice, and the log window and waveform viewer close with it.

Engineering notation

Value columns and the viewer readout format numbers in engineering notation with SPICE suffixes (f p n u m k Meg G T), about four significant digits: 4.096837e-04 displays as 409.7u. This is display-only — state files and dialog fields carry the raw values. To get scientific notation back, uncomment the prepared line in your rc file (sky130A/cadence_style_rc, gf180mcuD/cadence_style_rc or src/cadence_style_rc):

# set ase_eng_notation 0

Files in the run directory

FileWhat it is
<cell>.spiceclean circuit netlist (Netlist > Recreate); hand-editable, used by Run
<cell>_ase.spicefull simulation deck rendered by ASE for each run
<cell>_ase.rawwaveform data (overwritten in place each run)
<cell>_ase.logngspice output; source of the parsed result values

Scripting

Open a state from Tcl with ase::open_state <lib> <cell> <view> ?ro? — returns 1/0, never throws; re-opening an already-open state raises the existing window.

v1 limitations (honest list)

  • Launch and Tools menus are disabled placeholders; Results > Annotate entries (Operating Point info, DC Node Voltages) are disabled.
  • op-only results have no sweep and plot nothing (auto-plot and Direct Plot both report it).
  • Select On Design queues currents only for voltage-source/ammeter instances; per-terminal currents of other devices (savecurrents/@m names) are deferred.
  • Extra analysis keys from Analysis Options are stored and displayed but not yet emitted into the deck.
  • The Levels: entry in Save All is disabled.
  • Read-only open gates only the Save-As overwrite confirmation; it does not block edits.
  • Stop is unavailable on Windows.
  • No digital/mixed-signal lanes; the simulator is ngspice.
