## 4. The fix and the skip design (step 3)

**The checker** (`issue_stamp.tcl`, `proc istamp::history_probe`) classifies a tree once, at
`init`:

| state | evidence | what the gate does with an unresolved revision |
|---|---|---|
| `full` | `.git` here, `--show-prefix` empty, `--is-shallow-repository` = `false` | **problem (red)**, as before |
| `shallow` | same, but `--is-shallow-repository` = `true` | revisions that resolve are verified; those that do not are **NOT VERIFIED**, named in `last_skips` |
| `none` | no `.git` at this tree's root | git is **never asked** (`rev_verdict` returns `skip` before any exec), so a repository above cannot answer |
| `unreadable` | a `.git` git cannot read, git missing or timed out, or `--show-prefix` non-empty (another repo) | **treated as `full`: nothing skips, every revision question goes red** |

Quoted from the code, `proc istamp::rev_verdict`:
```
    if {$st eq "none"} { return skip }
    …
    if {[dict get $rev_cache $rev]} { return ok }
    if {$st eq "shallow"} { return skip }
    return bad
```
Only positive evidence of absence skips. Anything the probe cannot establish lands in `unreadable`,
which skips nothing (principle ii: never a silent pass). On `skip`, the gate **carries on**:
header window, grammar, baseline, `assert=` and the mirror check still run. Only the revision
question and `quote=` (which needs `git show <rev>:path`) are set aside. `gate` still returns only
problems, so no caller changed; `last_skips`/`last_verified` are new namespace variables. The CLI
prints `history: <state> -- <why>`, every `ISSUE-STAMP: NOT VERIFIED <item>`, and
`ISSUE-STAMP: ok (0 problems; 10 revision(s) NOT VERIFIED -- shallow: history absent)`.

**The suite** declares each row's need once:
```
set NEEDS_REPO    {S0 Q1 Q2}
set NEEDS_HISTORY {G4 D9h}
set NEEDS_GITBIN  {H1 H2 H3 H4 H5}
```
`check_needs` evaluates a row's script **only** if its need is met. Otherwise it prints
`skip: <row> -- NOT VERIFIED: <why>` and records the row in `::SKIPPED`. A skip never prints
`SKIP:` or `RESULT: SKIP` at column 0 (full_audit's and run_suites' whole-suite self-skip banners),
and a skip line never ends in `FAIL`. With no repository, `$REV` becomes the fixed legal token
`d64686a1` and git is not asked for HEAD, so the parse-level rows (S15, S15b, S15c, S17, G5, N3)
and the gate rows (B3, G2, A2-A4, N1-N2) still run.

**Principle by principle:**

* **(i) S20.** Compares the driver-side `$istamp::repo` with `$ROOT = [file dirname ×3 [file normalize
  [info script]]]`, derived from the *suite's* own location, so no folder name appears anywhere.
  +S20b: the driver's checker must reach the same history verdict and, where a repo exists,
  resolve HEAD. The driver is now written with `[list]`, and its `exec` is caught: a dying
  driver is a named FAIL, never a suite death.
* **(ii) Named skips.** Shallow skips G4 and D9h. Export skips S0, G4, Q1, Q2 and D9h. Every
  other row runs.
* **(iii) Full clone.** Nothing skipped (H7). Red rows stay red (section 6). D9b's both-direction
  self-test passes.
* **(iv) No new vacuous green.** Seven new rows:
  - H1: the probe classifies four known fixture repositories (full, shallow, none, unreadable),
    and git-free disk evidence agrees.
  - H2-H5: the gate's verdict `{problems skipped verified}` on six known corpora in each state.
    H2 shows a full history **refuses** a bogus revision and a rotted quote. H4's `none` fixture
    sits *inside* the full fixture, so `{0 1 0}` proves git was not asked. H5 shows an
    unreadable `.git` skips nothing.
  - H6: this tree's verdict equals the disk evidence (`.git`, git's own `shallow` file, a
    worktree's `commondir`), read without git.
  - H7: the skipped set is **exactly** the declared set for the state, which in a full clone is
    empty.
  - D9h: every well-formed stamped revision in the real corpus was verified (at least one, none
    skipped).

  The H rows need only the git program, so they run in the shallow clone and the export too.
  They are what proves G4's refusal there.
* **(v) Banner.** A skipping run ends `RESULT: ALL PASS (58 checks, 2 skipped -- shallow:
  history absent)` / `OVERALL: ok` / exit 0. This is the trailer shape `test_ase_bus_bits_0159`
  already ships.

**Cost.** MEASURED: `exec timeout 30 true` costs 104 ms against 0.8 ms bare, and the file's rule
wraps every exec in `timeout`. A first version took 16.7 s. Probing once per fixture state,
building the fixtures in one `sh` exec and memoising revisions within one `gate()` brought it to
**7.0 s** (the original suite: 3.5 s). The net cost is about 3.5 s on a T1 of about 260-380 s.

### Decision: `foreign` is gone, and the rule is per stamp

**`foreign` is not a state any more.** A tree with a readable history is `full`. The checker then
skips one stamp's revision, by name, only when there is positive evidence that the revision cannot
be in that history. The evidence: **the history's earliest root commit was authored on a later day
than the stamp's `stamped=` date.**
- The author date (`%at`) is used because a rebase or filter-repo keeps it.
- The earliest root is used, never the latest.
- The day is read at **UTC-12**, the earliest calendar day that instant falls on anywhere, and the
  comparison is **strict**. A stamp has a date but no zone, so a root on the stamp's own day, in any
  reading, does not count as provably after it.

Every other unresolved revision in a full history stays red. The fail-closed fallback in the task
(revert `foreign`, re-init goes red) was not needed. The per-stamp rule is fail-closed on every
shape measured below.

**New state `unborn`**, handled exactly as `none`: git is not asked about revisions, and the
NEEDS_REPO rows skip by name. It is its own name, not `none`, so that H6 can check it against the
disk (an unborn HEAD) and the output says what happened. It needs **all three** of these pieces of
evidence:
- `rev-parse -q --verify HEAD` exits 1 quietly;
- `for-each-ref` lists no ref at all;
- `cat-file --batch-all-objects` shows no `commit` object.

A failed ancestry walk that does not meet all three is `unreadable`. MEASURED on git 2.53:
- a gutted `.git` whose branch still names a lost commit answers `HEAD` with exit 0 and the name;
- it answers `HEAD^{commit}` with exit 1 (the same as unborn), which is why the probe asks for `HEAD`;
- an orphan branch in a repository that has history has an unborn HEAD but still has refs and
  commits.

**Ancestry.** `git rev-list --max-parents=0 --format=%at HEAD` must succeed, in full *and* shallow
trees. A failure is `unreadable` unless it is `unborn`.
- `rev-list` is plumbing and replaces `log`: `log` obeys the caller's `log.*` config, and `git_in`
  keeps config on purpose (for D7).
- MEASURED: noshallow gives `Could not read <c1>` / `Failed to traverse parents` with exit 128. A
  corrupt c1 gives `loose object … is corrupt` with exit 128. The main tree answers in 0.10 s.
