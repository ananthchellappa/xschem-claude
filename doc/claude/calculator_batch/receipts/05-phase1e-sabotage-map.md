## The three that reddened nothing

- **`B71`** — the Results Dir label's build-time `-text`.  A **no-op on the product**:
  `calc::results_refresh` runs at the end of `calc::build_res` and rewrites that label from
  `calc::results_label`, so the build-time string never reaches the screen.  `B71b`, which changes
  `calc::results_label`'s own default, reddens `W04 the label reads as a caption`.
- **`B75`** — `calc::fn_fill` stops resetting the canvas view on a category switch.  Out of this
  file's scope by design (it is a rendered-view fact, not an inventory one) and **covered by
  `test_calc_skeleton` S23**, verified by running the skeleton under this same sabotage:
  `RESULT: 2 FAILED (501 passed)` — `S23 switching category scrolls the new list back to its
  top-left` and `S23 ...and the head of the alphabet is on screen again`.
- **`C6b`** — the selector radio variable is not seeded before the widgets are created.  Reddens
  nothing because **Tk mints a missing `-variable` when the widget is created**, at its off value —
  which is precisely the trap spec W07's seeding rule exists for, and precisely why
  `W07 ::calc::selmode exists` is listed as unsabotaged rather than counted as evidence.
