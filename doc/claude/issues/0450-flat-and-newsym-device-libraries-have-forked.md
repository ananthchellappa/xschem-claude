# 0450 — `xschem_library/devices` and `xschem_libs_newsym/devices` have forked, and only one is installed

Status: OPEN, NOT FIXED. Filed by S6, which had to write its new symbol to BOTH
trees (decision D1) because neither one alone reaches every consumer.
Found: S6 (the PDK-neutral annotator carrier) on branch `annotate` at 9fe40128.

## What is wrong

Two device libraries ship in this tree and they are not the same library:

  * `xschem_library/devices/*.sym` — 125 flat cells. This is what
    `xschem_library/Makefile`'s `install -f -d devices/*.sym` glob installs, and
    the only one that reaches an INSTALLED xschem.
  * `xschem_libs_newsym/devices/<cell>/symbol/<cell>.sym` — 130 nested cells,
    git-tracked, generated by `tools/migrate/xschem_libmigrate.py`. NO Makefile
    anywhere installs it (`grep -rn xschem_libs_newsym --include=Makefile*` is
    empty), but it is what all three PDK workareas actually resolve `devices` to:
    every `xschem_libs/library.defs` carries
    `DEFINE devices ../../xschem_libs_newsym/devices`.

The contents already differ — newsym holds `ipulse`, `ipwl`, `vpulse`, `vpwl`
and `library.tag` that the flat tree lacks. Nothing detects the drift; a symbol
added to one tree is simply invisible to the other's consumers, silently.

## What S6 did about it

Wrote `annotate_params.sym` to both, byte-identical, and pinned the pair with
check K1 of `tests/headless/test_op_annot.tcl` ("both copies exist AND their
bytes are identical"). That is a guard for ONE cell, not for the library.

The byte-identical copy is safe only because this symbol has no `B` pin records
(nothing for the newsym pin-decoration pass to rewrite) and no `C {}` reference
(nothing for the migrator to re-point). A cell with either would need a real
migrate run, not a `cp`.

## The open questions

1. Which tree is canonical? If newsym is, the flat tree needs to become a
   generated artefact and the install rule needs to move.
2. Is the newsym tree meant to be installable at all, or is it in-tree PDK data
   only? Today an installed xschem cannot see it, so a PDK workarea copied out
   of this repo to an installed toolchain resolves `devices` to nothing.
3. Should a check enumerate the two trees and red on any cell present in one and
   absent from the other?
