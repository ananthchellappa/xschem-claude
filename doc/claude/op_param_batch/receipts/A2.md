## 4. Decisions, with the ladder rung and the rejected alternative

**(a) The name bit is set UNCONDITIONALLY, outside the `annot_class_free()`
gate.** Rung **L1**, invariant **I7**. The brief demanded this be justified in
writing, so:

The gate exists for **one named mechanism**, written down in the classifier
header block: the two class bits beside it are a **visibility authority** that
`text_hidden()` early-returns on **before** `show_hidden_texts`, so an implicit
class stacked on an explicit `hide=` would silently move that text from
*View > Show hidden texts* to the `annot_show` mask — and nine tracked
`pcb_current_protection_embed.sch` records really do carry both.
`TEXT_ANNOT_NAME` is deliberately **absent** from the content-class-to-mask
helper, which returns 0 for any bit it does not name, so it early-returns on
nothing and can move **no** text between switches. **The mechanism the gate
protects against does not exist for this bit.**

Run it forward to item A3, where the rung sits after the class tests and before
the `show_hidden_texts` fall-through. *Gated*: a user's own
`T {@name} … {hide=true}` gets no bit, A3's rung fires (the text carries neither
NAME nor a class) and the name is hidden **even with Show hidden texts ON** — a
name lost to the one feature whose promise is *"its name and the OP numbers,
nothing else"*. *Unconditional*: the rung does not fire and the text falls
through to exactly the `show_hidden_texts` / `HIDE_TEXT` pair that governs it
today. I7 holds in **both** directions, and the bit can never make a hidden text
appear.

**Measured first, and it does not discriminate**: zero of 4,823 shipped name
records carry a `hide=` token, so the two readings are byte-identical on every
file in this tree, in every PDK, today and after A3. **The measurement did not
back the choice** — it only proves the blast radius on shipped files is nil. The
choice is about the user's own future files, which is why it is also a `rule`
debt (§7).

*Rejected*: gating it inside the existing block for cosmetic consistency with
the two neighbours. The consistency is cosmetic — the neighbours are gated for a
mechanism this bit lacks — and it costs a name under the very feature that
promises to keep it.

**(b) A separate `annot_name_token()`, not a third arm of `annot_content_class()`.**
Rung **L2** (smallest blast radius). `annot_content_class` carries two rules that
exist **solely** because `load_sym_def()` rewrites an LCC-embedded
`@spice_get_voltage` into `@spice_get_voltage(<parentpath><lab>)` *before*
`set_text_flags` runs: the trailing-`)` argument rule and the `@#<pin>:` split.
Nothing anywhere rewrites a name spelling — `@spiceprefix@name` reaches
`set_text_flags` verbatim — so inheriting them would classify `@name(anything)`
as a name, which is not a whole-string match. And this class is unconditional
while `annot_content_class`'s result feeds the gated block, so folding them would
force a restructure of the caller. *Rejected*: a third return value; and the
middle road of an early special case inside it.

**(c) Copy the trim and the length-exact `strncmp`, and nothing else.** Rung
**L1**, invariant **I1** (one discipline, written once). The `strncmp` is
**forced, not chosen** — the trim walks two pointers into a `const` string and
cannot NUL-terminate it, so `strcmp` would mean allocating in a function called
per text per load. Measured: all 4,823 shipped name records are already exact
**without** the trim, so the trim is inert on this tree and is kept for the
user's own files and for the neighbour's discipline. Say that rather than
claiming the trim was load-bearing.

**(d) Placed before the gated block, not after.** Rung **L2** (testability at
zero semantic cost). A name spelling and a `spice_get` spelling are disjoint
whole strings, so the order is semantically free; before the block makes
"outside the gate" provable by a **line-index comparison** (row N8) instead of
by brace counting.

**(e) The render fixture is `cmos_inv`, not `nand2`.** Rung **L2**.
`src/cadence_style_rc` sets `XSCHEM_LIBRARY_PATH {}`; the suite **must** source
that rc (there is no `::cadence` without it), after which
`xschem_library/examples/nand2.sch` loads with eight unresolved symbols and
renders **zero** symbol text — so rows I2/I3 are byte-identical at every mask for
a reason that has nothing to do with the mask. That is issue **1248**.
`xschem_libs_newsym/examples/cmos_inv/schematic/cmos_inv.sch` loads cleanly under
the **same** rc (14 instances, 2 texts) and carries all three spellings on one
sheet: `M1`/`M2` from `@spiceprefix@name`, `R1`/`V1`/`Vmeas` from `@name`, and
the schematic-own literals `@name` and `@symname`. *Rejected*: extending row I2
or its fixture — the brief and 1248 both forbid it, and replacing it is A3's
obligation.

**(f) File `draw.c:873` as 1249; do not fix it.** Rung **L2** plus the crew rule.
Three byte-identical copies in three files A2 does not own. Row **N14** pins the
defect behaviourally so the filing carries evidence rather than prose.

**(g) The issue number came from `NUMBERING.md` and nowhere else.** Rung **L2**.
The brief's *"number from 0619 upward"* and its *"HARD CEILING: do NOT file past
0499"* are mutually contradictory **and both false on this tree**; `CREW_BRIEF.md`
is explicit that numbers come from `NUMBERING.md`, so the brief loses. Item A1
recorded the same thing. **The driver should fix the brief template.**

## 5. The honesty limit, said before the suite is read as more than it is

**The new bit is unobservable from Tcl, and the obvious probe silently lies.**
`xschem get text_flags` does not raise — it returns the **empty string** through
the generic `get` fall-through, with or without an index; only
`xschem text_flags 0` errors. `src/scheduler.c` reads `text[i].flags` in exactly
one place (a `TEXT_FLOATER` test) and never exposes `text_hidden`. A reflection
accessor means editing `scheduler.c`, which A2 does not own.

Therefore:

* **positive** evidence is **structural** — the anchored `#define`, the eleven
  distinct powers of two, and **C function-body slices** (`dc_cbody`, the C
  analogue of `opa_proc_src`). A whole-file grep would be satisfied by A2's own
  comment, which names all three spellings; sabotage SB-A2-2 proved that
  experimentally.
* **behavioural** evidence can only be **negative** — "nothing moved".

Two things were done to close that gap **outside** the suite, and they are
reported as extras, never as suite checks:

1. `annot_name_token` was extracted verbatim from the built `src/actions.c` into
   a standalone harness and compiled `gcc -std=c89 -Wall -Wextra -pedantic`:
   **zero diagnostics**, 23 cases + NULL, **0 mismatches** (the implement pass);
   26 cases + NULL, 0 mismatches (verify-B, independently). Accepts all three
   spellings and their padded forms; rejects `x=@name`, `name=@name`, `@names`,
   `@name_foo`, `tcleval(@name)`, `@name(x)` (proving the `()`-rule was correctly
   **not** inherited), bare `name`, `@symnam`, `@spiceprefixname`, the shipped
   multi-line `@name\n@value` forms, the empty string and a bare `@`.
2. The adversary broke on `text_hidden` under **gdb** and printed its `flags`
   argument for a 16-text symbol and a 5-text schematic: `flags=1024` for all
   three spellings **and** the padded ` @name ` under `ctx=1`, `flags=0` for
   twelve near-misses, and `1024` / `1040` (`|TEXT_FLOATER`) / `1032`
   (`|HIDE_TEXT`) under `ctx=0`. That is the direct positive proof the suite
   cannot give, and it also shows the bit riding alongside every `hide=` bit
   without changing what each answers.

**Nothing moved on screen, proved cross-binary.** The measure pass's own
`before.tcl` was replayed against the **new** binary: the warmed SVG exports at
`hide_symbols` 0 and 2 and at `annot_show` 0/1/8/9 are `cmp`-**identical** to the
pre-change files (26,877 bytes, md5 `495e021eacaae5f245def84368080e5d`), and the
round-trip `.sch` is md5 `487592c7503e6ffe9cb4f92ed985da3e` on both sides. That
is strictly stronger than rows N11/N12, which only compare masks to each other.
The adversary added a 60-schematic sweep across `xschem_library`,
`xschem_libs_newsym`, sky130A, gf180mcuD and ihp-sg13g2: **60/60** byte-invariant
across masks 0/1/8/9, 0 load errors, `modified` never set.

**Why it is a no-op by construction, not by care.** Every read of a text struct's
`.flags` in `src/*.c` is a named-bit test or a call into
`text_hidden`/`annot_text_layer`; all three bit-readers name only bits they
enumerate; there is no wide-mask test anywhere, and the only `& 1024` in the tree
is on `xRect.flags`, a different struct. `grep -rn TEXT_ANNOT_NAME src/` shows
**one write and zero reads**.

* **`tests/headless/test_op_annot.tcl`'s tripwire U35 counts `annot_class_mask(`
  — the name followed by an open paren.** A comment may name that function

  as a class.
