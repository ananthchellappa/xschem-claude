## The three refutations, each REPRODUCED FIRST-HAND before the decision

The write-up agent did not take Verify-C's word for any of them.

### (1) issue **1306** — the focus hand-back bounces a DELIBERATE click into the text pane

The fix's third narrowing is reasoned from bindtags and the real mechanism is
X's **ancestor `FocusIn` chain**. Measured on `:99`/openbox:

```
FocusIn seen: {.rdw NotifyNonlinearVirtual} {.rdw.p NotifyNonlinearVirtual} {.rdw.p.t NotifyNonlinear}
after  click: focus=.drw  pending=0
VERDICT: TEXT FOCUS BOUNCED TO CANVAS
```

`%W` **is** `.rdw`, so the guard passes. And the armed flag is reachable —
**both halves in ONE process**, `xvfb-run -a`, no window manager, a real
first-of-session noun-verb dump:

```
after real dump:  focus=.drw  pending=1
after text click: focus=.drw  pending=0
VERDICT: BOUNCED - the copy target lost the keyboard
```

The code's stated cost says the leftover flag hits *"the window's FRAME — not
its text"*. **It hits the text** — the pane the user's own stated use (paste
dumps into design-review documents) depends on.

### (2) issue **1305** — a key pressed while a descend has the mode SUSPENDED seizes the canvas for the session

`rdw::pick_start`'s guard lets a suspended mode fall through into `_pick_seize`
without clearing `pick(suspended)`, so the later `resume_all` seizes a second
time and latches **the seize's own scripts** as the predecessors. Measured,
`:99`/openbox:

```
after key    suspended flag STILL set = 1
resumed      P='rdw::pick_click; break'  R='break'  E='rdw::pick_end; break'  M='break'
after ESC    P='rdw::pick_click; break'  R='break'  E='rdw::pick_end; break'  M='break'
VERDICT: PERMANENT SEIZE - ESC restored the seize onto the canvas
second ESC returns: 0
```

Every click dumps, nothing can be selected again, the rubber band is dead, and
the mode's own advice *"press ESC to leave"* cannot work. That is the **inverse**
of the user's ruling sentence. The **control** names the cause:
`ase::ui::select_on_design` runs the identical sequence clean, because it ends
the previous mode first — the very thing `rdw::pick_start`'s comment argues
against copying.

### (3) issue **1307** — a new window inherits a live seize (and this one is TRUE OF THE TREE TODAY)

`clone_canvas_bindings` copies `.drw`'s bindings onto every new canvas
(`xinit.c:2121`, `:2337`); `pick_end`/`sod_end` clean only the canvas they
seized. `cmdmode.tcl:44-50` documents the hazard and its invariant covers **only
the descend chain**. Measured against **shipped ASE on the reverted tree**, with
`rdw::pick_start exists = 0`:

```
.x1.drw P='ase::ui::sod_click probe; break'  E='ase::ui::sod_end probe; break'
after ESC on the parent:  .drw P=''   .x1.drw P='ase::ui::sod_click probe; break'
VERDICT: ASE LEAKS THE SAME WAY - true of the tree today
```

⚠ **1304's fourth sequence widens 1305 and 1307 both**: `<B1-Motion> {break}`
joins the leaked set, so 1304's *transient* harm becomes *permanent*.
