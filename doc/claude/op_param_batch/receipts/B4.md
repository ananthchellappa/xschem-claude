## Why it was reverted anyway

The adversary refuted the central claim on three counts and **this agent
reproduced the sharpest one first-hand before deciding**, headlessly, on the
shipped `xschem_library/examples/cmos_inv.sch`:

```
exact  175.175 -199.612 -> 'M1'
snapped 180 -200        -> 'R1'
unsnapped accessor exists? [catch {xschem get mousex} m] -> 0 -> ''
```

`rdw::pick_click` can only read the **snapped** pair, so the window names a
device the user did not click — 6.4% of in-bbox points miss, 0.5% resolve to
another device, silently. That is invariant **I3**'s plausible-wrong-answer
class one object out from a number (issue **1303**).

Second, the seize copied from `ase::ui::select_on_design` takes press, release
and Escape and **not `<B1-Motion>`**, so 1 px of drift left `ui_state 16` alive
after `ESC` and an eight-step drag **selected 13 objects** — against the user's
own *"clicking will not change selected set"* (issue **1304**). I verified both
binding shapes are byte-identical in shipped `src/ase_window.tcl`, which is why
these are issue files and not merely patch holes.

Third, on the **first** dump of a session `ESC` cannot leave the mode at all:
`rdw::open` ends in `focus .rdw` and `_focus_canvas`'s `focus -force` loses the
race against the WM mapping the toplevel. Row `V8` was written for exactly this
and passed, because the row before it had already mapped `.rdw` by a different
path.

Two more holes, neither fenced: deleting `rdw::open` from `rdw::show` reds
**nothing** while making the first press of a session invisible; and a
**refused** key still moves `::rdw::listkind`. All five are tabulated in
`PLAN.md`'s B4 section with their fixes.
