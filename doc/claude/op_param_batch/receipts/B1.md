## Then the adversary, and then this agent

The adversary reported three "BROKE IT" attacks. This agent re-drove the
headline one independently, after the fact, on the same working tree, and it
reproduces — but **only through a binary raw**, which is the flavour a real
`write` produces:

```
raw value -1 : <nan>
raw value  0 : <nan>
raw_or_blank : <nan>          <-- string is double -strict says YES
_finite      : 0              <-- the only thing that says NO
ANSWER: devices {@m.x1.m1 {{id nan} {gm 0.5}}} absent {} complete 0 state ok
```

`nan` in the **value** bucket of a seam whose own documented contract says
`absent` carries *"columns the raw NAMES but the simulator did not compute"*.
Item B3 rendering that unfiltered puts `id = nan` on a schematic — verbatim what
invariant **I3** forbids. Every other consumer of `raw_or_blank` in the tree
passes the number through `op_annot::_finite` first (four call sites in
`src/op_annot.tcl`, one in `eng_or_blank`); `op_param_set` was the first that did
not. Filed as **1272**, with the recommended fix and its rejected alternatives.

**The sharpest sentence in this receipt:** the suite was **green at 37/37 and the
seam was wrong**, because the suite had no non-finite row. That is A7's lesson
arriving in a new costume — not a measurement taken at the wrong seam this time,
but a fence built around every question the author had thought of.

An **ascii** raw hides the same failure differently and worse: `nan` reads back
as `0`, `inf` as `0`, `1e999` as `1.0000001e+38`. `src/save.c` documents that
`my_atof()` flattening as a known, deliberate inconsistency and records that
`ngspice-46 on this box` emits all four non-finite spellings. So the same failed
simulation reports `nan` one way and a confident `0` the other.

Second finding, independently reproduced, narrower:

```
norm(a.b.c)  : <b.c>
req @m.a.b.c : devices {@m.a.b.c {{id 7} {gm 8}}} ... state ok
req a.b.c    : devices {} absent {} complete 0 state ok
```

`ase::op_dev_norm` drops **any** leading one-character segment, to make the
element letter irrelevant per ruling D-3. A legitimate hierarchical request whose
first segment is one character (`a.b.c`) therefore loses that segment and the
device silently vanishes — reported as `state ok, devices {}`, which is
byte-identical to "unknown device". Not filed as a tree issue because the code is
reverted; it is a **binding constraint on the reconstruction** and is recorded in
`PLAN.md`'s B1 entry.

## Driver adds, both answered

**(1) Q10 — MEASURED AND RECORDED, NOT GATED ON. The answer is YES.** With real
ngspice, `ngspice -b -r q10m.raw q10m.cir` on a `v`+`r`+`c` deck carrying `.op`
then `.tran` writes **one** file holding **two** plots (`Operating Point`,
3 vars, 1 point; then `Transient Analysis`, 4 vars, 112 points). `xschem raw read
<f>` with no sim_type lands on the OP plot (`sim_type=op`), `xschem annotate_op
<f> 0` publishes (`raw annot` = `0 0 -1`), and `raw value <v> -1` returns real
device numbers. **So an op slot IS reachable in the raw registry after an
ordinary OP+TRAN run**, and `update_op()`'s op/dc guard is never reached with
`sim_type=tran` on that path. Two caveats, both measured: on the `.control` +
`write` writer the second `write` **overwrites** the first without `set
appendwrite`; and once someone reads the tran slot it becomes **current**, at
which point `raw list` and `raw value` answer about the transient. This is B3's
suite's first check and it can now be written as an assertion, not a question.

**(2) A row that reds if the declaration is replaced by a probe** — delivered as
two, and both verified red under the `SAB-PROBE` variant: `C3` counts the
forbidden tokens (`exec`, `sim_capabilities`, `cap_workdir`,
`sim_probe_capability`, `blanket_op_save`, pipe-open) in **both** new bodies and
expects zero; `C4` clears the capability cache, renames the three doors aside as
recorders, calls the hook and asserts nothing was reached and no probe folder
appeared.

## Still open

From the adversary, and from this agent's own re-drive. The first two are
**blocking** on the reconstruction; the rest are contract questions B2/B3 inherit.

1. **The non-finite leak — issue 1272.** One line at the read: gate on
   `::op_annot::_finite` and route a non-finite somewhere other than the value
   bucket. Plus a suite row with a **binary** fixture, since ascii hides it.
2. **The one-character-segment over-strip.** `op_dev_norm` must strip the element
   letter without eating a legitimate one-character hierarchy segment. Cheapest
   correct rule: strip a leading `<letter>.` only when the letter is one of
   ngspice's element letters *and* the remainder still contains a `.`; or better,
   compare on the **tail segments** rather than by normalising a prefix away.
3. **`state ok, devices {}, absent {}` is three situations wearing one answer** —
   unknown device, over-stripped request, and a device the raw names only through
   columns with no `@`. That ambiguity is the same class the four non-`ok` states
   were introduced to remove.
4. **`complete` conflates two claims** — "this backend can enumerate" and "this
   answer is complete". Inert today because the only backend declares `0`; the
   moment a custom build declares `1` the flag claims completeness over whatever
   the deck happened to save. Rename (`backend_enumerates`) or split before B2/B3
   build on it.
5. **A DC slot answers `state ok` from a multi-point sweep** — measured, a 3-point
   dc raw published point 0 as "the operating point" with no indication the run
   was swept. Consistent with `update_op()`'s own allow-list, and still silent.
6. **The seam never checks the raw belongs to the sheet being asked about.** A raw
   loaded from another schematic answers `ok` with confident numbers under the
   requested devpath. The `op` gate stops a transient, not a foreign OP.
7. **The device key handed back is the raw's own spelling**, bus index mangled
   included (`@m.xm1[9.0]…` where the deck wrote `[9:0]`). A caller comparing it
   against `op_annot::devpath`'s mint will not match, and nothing pins the two.
8. **No row asserts the seam is read-only.** Verified by hand across 75 calls
   (modify flag, `.sch` bytes, raw registry) and nothing stops a later edit adding
   a slot switch — `xschem raw switch` is one line away.
9. **`rule` debt `1245_B1_not_op_refusal` is on the owed ledger and unratified.**
   The `not_op` refusal is user-visible on **B3's** surface: key 3 pressed while a
   transient is loaded will say "no operating point" rather than silently printing
   transient numbers. That is the right answer and it is still the user's to make.
