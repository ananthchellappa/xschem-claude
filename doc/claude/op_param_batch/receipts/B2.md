## 4. Evidence

**The headline — the IHP triple survives.** `seed mos` with `ihp-sg13g2`
registered answers `{id ids 0} {gm gm 1} {gds gds 1} {vgs vgs 2} {vth vth 2}
{vds vds 2}`; the first entry has `llength` 3, `lindex 0 0` = `id`,
`lindex 0 1` = `ids` — **they differ** — and it round-trips
write → reset → load unchanged with zero reports. sky130 and gf180 alone cannot
see this: both spell it `{id id 0}`.

**Nothing in the settings file is ever executed, asserted as a side effect and
never a return code.** A conf whose **first two** lines (under a friendly
header — the ordering is load-bearing, since payload-last would abort a `source`
before it ran) are `set ::OPL_PWNED 1` and `exec touch <scratch>/PWNED` leaves
`::OPL_PWNED` unset, creates no file, reports and skips both lines, and the data
row after them still loads. Substitution shapes (`[exec …]`, `$env(HOME)`,
`${x}`) are stored as literal text. Structurally: zero occurrences of
`subst` / `uplevel` / `source ` / `exec ` / `eval` outside comments.
**Counterweight:** a dollar, a bracket, a **lone open brace**, a backslash, a
slash and a mid-token hash all load and round-trip with zero reports — the
parser is strict, not merely refusing. (Fields are split with
`regexp -inline -all {\S+}`; the lone `{` would have raised inside an
`llength`-based reader.)

**An interrupted write never truncates.** With `<path>.new` made a **directory**
(so the open fails for root as well) `write_conf` returns 0, the pre-existing
file is byte-identical, the new entry is absent from it, and the failure is
reported in plain English. A `0600` the user set survives the rename; a missing
`.xschem` directory is created rather than reported.

**D-7, both halves in one check.** A user entry for `mos annotation` overrides
its class **and** `bipolar annotation` is still the PDK seed. The project file
beats the user-global one per list, and the user-global's `mos summary`
survives. A missing file at either tier is the ordinary first-run case.

**The class map is data.** `info body ::op_param_lists::class` contains no
`switch`; a `class esd diode` row adopts a new token and `class nmos widget`
overrides a shipped default, both surviving write + reload. An unmapped token is
its **own** class — `varactor`, `esd`, `inductor`, `pnp`, `npn`, `2N3906`,
`pwell_resistor` all answer themselves, no raise.

**The locale row runs in a child.** `env LC_ALL=C LANG=C ./src/xschem --nogui …`
reports `encoding system` = `iso8859-1` (the control) and still reads the
non-ASCII label back as the same bytes; the file it writes carries the UTF-8
bytes twice and the latin-1 bytes zero times.

### Measured and not fixed

* **1274** — `op_annot` publishes no registration order, so *"first registered
  wins"* is unimplementable as stated. Lexical order shipped; one-line repair
  named; B2 may not edit `op_annot.tcl`.
* **1276** — `write_conf` returns **1 with no report** when the target is a
  **directory** (the temp is moved *inside* it) or a **symlink** (replaced by a
  regular file, real target untouched). Atomicity and the never-truncate row
  both hold; *"returns 1, or 0 with a report"* does not.
* **1277** — the **flavor glob wins by `lsort` order**, not narrowness or file
  order (`*fet*` beats `*nfet_01v8*` in both insertion orders; the winner flips
  when the *loser* is renamed), and a flavor key carries **no class**. The class
  field is a **grammar** change, so it must be settled before B5 writes the
  first flavor entry.
* **1278** — an unbounded `string match` pattern from a shared file **freezes
  the consumer** (0.85 ms / 14.6 ms / 129 ms / 11.6 s / >70 s at 5/7/9/11/13
  stars), accepted at load with zero reports. DD-3's parser is safe; the
  consumer is not. Part 2: the reader's duplicate check is quadratic.
* **1279** — bare `apply` iterates the class map, so a type the map does not
  name is never a candidate: the list is stored, correct, and **invisible**
  (`gen` never moves — invariant I5 failing silently).
* **1280** — `apply` writes list 1 into `params` and `op_annot::_cards_for`
  emits one `.save` per `params` row, so **trimming the annotation list stops
  the deck saving what the summary list asks for** and those rows go permanently
  blank (R1, I3). ⚠ its fix carries a **user question for B5**: does Delete stop
  *drawing*, or stop *saving*? (spec Q17)
* **1281** — writing the **project** file exports the author's **user-global**
  map and lists into it; the store keeps no provenance. For a file whose
  headline feature is shareability, Save checks in one person's personal taste.
