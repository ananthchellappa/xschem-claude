## ⚠ THE HEADLINES

### 1. The answer is YES, and it is stronger than "it parses"

Every `.s2p` produced by ASE-L's shipped export path — `ase::backend::ngspice::render_deck`
with an `sp` row carrying `s2p 1`, six files across three benches and both binaries — parsed in
**scikit-rf 2.1.0** on the first attempt, with **no warning**, and read back as the
2-port / 11-point / **50 Ω** / **Hz** file its header claims.

And the values are right. Against **ngspice's own doubles for the same sweep** — read out of
the `.raw` by a separate ngspice invocation, never out of the `.s2p` — the frequency axis
agreed **exactly** (`0.000000e+00` Hz on all eight files) and the S matrix agreed to
**0 violations out of 44 components** of a *derived* bound.

⚠ **THE TOLERANCE IS DERIVED, NOT NAMED.** `wrs2p` writes `%.6e`, so the residual can only be
7-significant-digit decimal rounding. The bound is computed per component
(`0.5e-6 × 10^floor(log10|v|)`, combined over re/im) and nothing exceeds its own: bench A
`max(|ΔS|−bound) = −4.50e-12`, bench B `+0.00e+00` (exactly on it), bench C `−1.53e-10`. So the
claim is **"they agree to the full precision the format can carry"**, not "they agree to 1e-6".

### 2. ⚠ THE `unlet` IS NOT A TOUCHSTONE CORRECTNESS REQUIREMENT, AND THE DEBT SHOULD SAY SO

The brief framed this as *"if an independent reader rejects or misreads that file, the `unlet`
is not housekeeping but a correctness requirement"*. **Measured: the reader does neither,
because the file is byte-identical.**

```
shipped (with unlet):   No. Variables: 20        .s2p md5 5b892d5e…
no-unlet variant:       No. Variables: 21        .s2p md5 5b892d5e…
                            16  rbase  notype dims=1
```

M12's first half is confirmed exactly — the leak is real, on both binaries — but it is confined
to the **`.raw`**. The Touchstone consumer never sees it, and the §4 agreement table's two
no-unlet rows are digit-for-digit the shipped rows. **The `unlet` earns its place by keeping a
column the user never asked for out of the results file**, which is the reason
`sp_export_lines`' own comment gives. Nobody should be told it protects the `.s2p`.

### 3. ⚠ MY FIRST BENCH COULD NOT HAVE CAUGHT THE MOST LIKELY DEFECT

Touchstone's 2-port line order is **S11 S21 S12 S22** — the one exception in the format, where
every other port count is row-major. A transposed S12/S21 would parse perfectly and be wrong.

`test_ase_sp_1452.tcl`'s bench is a resistive attenuator and my bench A is a reciprocal LC, and
**on a reciprocal network the swap is invisible**: the transposition control on bench A reads
`5.83e-08`, i.e. exactly the agreement figure, with reference asymmetry `0.000000e+00`. It
would have passed with the defect live.

So bench **B** was added — a VCVS, S21 ≈ 12.7 and S12 **exactly 0**, control `1.269841e+01`.
Against a bench that could have proved otherwise, **ASE-L's file is in Touchstone's 2-port
order.** This is the batch's own recurring shape (*a guard against absence must itself be
tested against absence*) arriving in a numerical check.

### 4. ⚠ THE `# Hz S RI R 50` LINE IS THE FILE'S MEANING

Deleting the option line does **not** produce an error. Touchstone's documented default is
**GHz / MA / R 50**, scikit-rf applies exactly that, and the file parses cleanly while being
wrong by the size of the data:

| the file | f[0] | max\|ΔS\| vs the truth |
|---|---|---|
| as ASE-L writes it | 1.000000e+06 | **5.825805e-08** |
| `#` line deleted | **1.000000e+15** | **8.057927e-01** |
| `# GHz S MA R 50` forced | 1.000000e+15 | 8.057927e-01 |

Forcing `R 75` moves scikit-rf's `z0` to 75 and nothing else, so `R` really is carrying port
1's Z0 as `sp_export_lines` intends. **SE1 already pins that literal**; this says what the pin
is worth.

### 5. The 3-port file is well-formed and cannot say it is a 3-port

`sp_row_check` cautions rather than refuses, so a user can tick the box on a three-port
analysis today. ngspice says `Note: only 2 ports 1 and 2 are supported by wrs2p`, rc 0, and
writes a **valid 2-port file** holding the exact (1,2) submatrix (0/44 violations). Nothing in
it distinguishes a two-port network from two ports of a three-port one — different objects to
anyone cascading them. **ASE-L's caution is the only place that information exists.**

reader is discriminating on content, not echoing.
