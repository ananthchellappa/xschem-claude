## 0. The answer

**Yes.** Every `.s2p` ASE-L's shipped export path produced parsed on the first attempt, read
back as the 2-port / 11-point / 50 Ω / Hz file its header claims, and carried **the numbers
ngspice itself computed, to the full precision the file format is capable of** — zero residual
above a derived decimal-rounding bound, on both binaries, on three benches. The frequency axis
agreed **exactly**, to `0.000000e+00` Hz.

Three findings come with it, and one of them narrows what the `unlet` is for:

1. **The `unlet Rbase` is NOT a Touchstone correctness requirement.** The `.s2p` is
   **byte-identical** with and without it. The leak is confined to the results file.
2. **The `# Hz S RI R 50` line is load-bearing and ASE-L gets it right.** Remove it and
   scikit-rf still parses the file — silently, as **GHz / MA**, which is Touchstone's
   documented default — turning 1 MHz into 1 PHz.
3. **A three-port `sp` row with the Touchstone box ticked writes a well-formed 2-port file
   that records nothing about the third port.** ASE-L's caution is the only thing that tells
   the user.

## 1. How the files were produced — ASE-L's own path, not an imitation

Each file came out of `ase::backend::ngspice::render_deck` driven by an
`ase::state_default` state with an `sp` row carrying `s2p 1`, exactly as section **SE** of
`tests/headless/test_ase_sp_1452.tcl` does it. The tree's own answers, printed by the driver
script rather than transcribed:

```
S2PFILE:  <rundir>/m12bench_ase_sp1.s2p
EXPORT:   {let Rbase = 50} {wrs2p <rundir>/m12bench_ase_sp1.s2p} {unlet Rbase}
ALTER:    {alter v1 portnum = 1} {alter v1 z0 = 50} {alter v2 portnum = 2} {alter v2 z0 = 50}
CARD:     sp lin 11 1meg 200meg
```

⚠ **THE BENCH IS REACTIVE ON PURPOSE, AND THE SUITE'S IS NOT.** `test_ase_sp_1452.tcl`'s
bench is a 50/50/50 resistive attenuator, so **every S value is real and flat in frequency**.
A reader that misread `RI` as `MA`, or Hz as GHz, would agree with such a file anyway — the
imaginary parts are zero and there is no frequency dependence to get wrong. So bench A here is
an LC low-pass (`l1 in out 100n`, `c1 out 0 40p`), which makes S complex and strongly
frequency-dependent, and the three misreadings the debt names all become detectable.

| bench | netlist | why it exists |
|---|---|---|
| **A** | `l1 in out 100n`, `c1 out 0 40p` | complex, frequency-dependent S; the main case |
| **B** | `e1 amp 0 in 0 10`, `rout amp out 25`, `c1 out 0 5p` | **non-reciprocal** — see §4a |
| **C** | three ports, `r1/l2/c3` into a common node | the 3-port case ASE-L permits — §6 |

Six files went through the shipped path (3 benches × 2 binaries). Two more are the
counterfactual of §5.

## 2. Measurement 1 — does it parse?

`rf.Network('<file>')`, all six shipped-path files, both binaries:

```
PARSE: OK
```

No exception, and **no warning** — captured with `warnings.simplefilter("always")`, which
reported `NONE` for every file.

**The control, because a reader that accepts everything proves nothing.** The same call on
four deliberately broken inputs:

| input | what scikit-rf did |
|---|---|
| a path that does not exist | `FileNotFoundError: [Errno 2] No such file or directory` |
| a zero-byte file | `EOFError: Ran out of input` |
| two lines of prose | `ValueError: could not convert string to float: 'this'` |
| **the real file with the `#` option line deleted** | ⚠ **`PARSE: OK`** — see §7 |

So the reader does reject, and the three rejections above are what makes `PARSE: OK` on our
files mean something.

## 3. Measurement 2 — does it read back as what we think we wrote?

Identical on all six, on both binaries:

NPORTS: 2          Z0-UNIQUE: [50.+0.j]      S-DTYPE: complex128
NPOINTS: 11        Z0-SHAPE: (11, 2)         S-SHAPE: (11, 2, 2)

Two ports, eleven points, **50 Ω on every port at every frequency**, units Hz — which is what

and contains **no CR bytes**.

**And scikit-rf agrees with itself about it**: writing each network back out with

### The tolerance, and why it is derived rather than named

⚠ **There is no arbitrary epsilon here, because there is no room for one.** `wrs2p` writes
`%.6e` — seven significant decimal digits — while the raw carries full doubles, so the residual
**must** be the decimal rounding and nothing else. The bound is computed per component: half a
step of a 7-significant-digit decimal, `0.5e-6 × 10^floor(log10|v|)`, combined over real and
imaginary parts. **Not one of the 44 complex components of any file exceeds its own bound**,
and bench B sits exactly *on* it (`+0.000000e+00`). Bench B's larger absolute figure is
arithmetic, not disagreement: its S21 is ≈ 12.7, so one decimal step there is 1e-5 where on
bench A's ≈ 1.0 values it is 1e-6.

So the correct statement is not *"they agree to 1e-6"*. It is: **they agree to the full
precision the Touchstone text is capable of carrying.**

**The non-vacuity control**: perturbing one reference value by 1e-3 moves the comparison to
`1.000000e-03`, so the comparison can disagree.

### 4a. ⚠ The transposition check, and the bench that was blind to it

Touchstone's 2-port line order is **S11 S21 S12 S22** — the single exception in the format,
where every other port count is row-major. If ngspice emitted the off-diagonal pair row-major
and scikit-rf read it Touchstone-wise, **S12 and S21 would be silently swapped and every number
would still parse**. This is the most plausible real defect in the whole area.

**On a reciprocal network that swap is invisible.** Measured, and it is why bench B exists:

| case | max\|S − refᵀ\| | reference S12/S21 asymmetry |
|---|---|---|
| A (LC, reciprocal) | 5.825805e-08 | **0.000000e+00** ← the check cannot fail here |
| C (3-port, reciprocal) | 6.506919e-08 | **0.000000e+00** ← nor here |
| **B (VCVS, unilateral)** | **1.269841e+01** | **1.269841e+01** |

Bench B's S21 is ≈ 12.7 and its S12 is **exactly 0**, so a transposition would be a 12.7-sized
error. It is not present: the agreement in §4 holds on bench B term by term
(`S12-MAX-ABS-DIFF: 0.000000e+00`, `S21-MAX-ABS-DIFF: 3.600002e-06`). **ASE-L's file is in
Touchstone's 2-port order, measured against a bench that could have proved otherwise.**

### 4b. The RI-read-as-MA control

Had the eight data columns been read as magnitude/angle-in-degrees instead of real/imaginary,
the error would be **8.057927e-01** (bench A) and **1.027023e+00** (bench B) — i.e. the same
size as the values themselves. The measured agreement is eight orders of magnitude below that.

## 5. Measurement 4 — the `unlet` leak, through the same reader

The variant is a **post-process of the rendered deck**, not a change to ASE-L: `unlet Rbase` is
dropped from a copy of the text `render_deck` produced, and the output paths are renamed so the
two runs cannot overwrite each other. `src/ase.tcl` was not touched.

The first half of M12 is confirmed exactly, on both binaries:

```
shipped (with unlet):   Plotname: SP Analysis   No. Variables: 20
no-unlet variant:       Plotname: SP Analysis   No. Variables: 21
                                                    16  rbase  notype dims=1
```

⚠ **AND THE TOUCHSTONE FILE IS UNAFFECTED — BYTE-IDENTICAL.** Both `.s2p` files carry md5
`5b892d5e…`; `diff` past the generated-at line is empty; scikit-rf reads them to the same
values, and the §4 table's two no-unlet rows are digit-for-digit the shipped rows.

**So the `unlet` is results-file housekeeping, and the debt should say so.** It keeps a column
the user never asked for out of the `.raw` that every downstream surface then has to explain —
which is a real reason, and the one `sp_export_lines`' own comment gives. It is **not** a
correctness requirement for the Touchstone consumer, and nobody should be told it is.

## 6. The three-port file — ASE-L permits this, and the file cannot say so

`ase::backend::ngspice::sp_row_check` cautions rather than refuses. Its verbatim answer for
bench C, printed from the tree:

```
caution {a Touchstone file holds exactly 2 ports and this analysis has 3, so only ports 1
         and 2 will be written}
        {reduce the analysis to 2 ports, or read the file as the 2-port it is}
```

ngspice agrees, once, on stdout: `Note: only 2 ports 1 and 2 are supported by wrs2p`. The run
is rc 0 on both binaries and the SP plot holds **39** variables (the full 3×3 S/Y/Z).

What lands on disk is a **well-formed 2-port Touchstone file**: 16 lines, 9 columns, header
`# Hz S RI R 50`, `!2-port S-parameter file`, and scikit-rf reads it as `NPORTS: 2`. Its values
are the exact (1,2) submatrix of the 3-port result — §4's C rows, 0/44 violations.

⚠ **The file records nothing about the third port.** Nothing in it distinguishes "a two-port
network" from "two ports of a three-port network, with the third terminated in its z0", and
those are different objects to a user cascading it in ADS or Qucs. **ASE-L's caution is the
only place that information exists**, which raises what that sentence is worth — it is not
decoration, it is the file's missing metadata.

## 7. ⚠ The option line is what makes the numbers mean anything

Measured against bench A's reference:

| the file | f[0] read back | max\|ΔS\| vs the truth | z0 |
|---|---|---|---|
| **as ASE-L writes it** | 1.000000e+06 | **5.825805e-08** | 50 |
| with the `#` line **deleted** | **1.000000e+15** | **8.057927e-01** | 50 |
| with `# GHz S MA R 50` forced | **1.000000e+15** | **8.057927e-01** | 50 |
| with `# Hz S RI R 75` forced | 1.000000e+06 | 5.825805e-08 | **75** |

A missing option line is not an error to a Touchstone reader — it is **GHz / MA / R 50** by
specification, and scikit-rf applies exactly that. The deleted-header file parses cleanly and
is wrong by the size of the data. So `# Hz S RI R 50` is the whole difference between a correct
file and a plausible one, and the `R 50` really does come from port 1's Z0 as
`sp_export_lines` intends (forcing `R 75` moves scikit-rf's `z0` to 75 and nothing else).

## 8. The passivity verdict, traced rather than reported

scikit-rf answers `is_passive() = False` for bench A. Bench A is **lossless** — L and C only —
so its S matrix is unitary and sits exactly *on* the passivity boundary. Traced:

```
maxSV from the .s2p TEXT    = 1.000000063287   (over 1 by +6.329e-08)
maxSV from the RAW doubles  = 1.000000000674   (over 1 by +6.738e-10)
is_passive(file) = False    is_passive(raw-rebuilt) = False
```

**Both are over 1, so this is not caused by the Touchstone text** — ngspice's own doubles are
already 6.7e-10 above unity, and the 7-digit rounding adds the rest. A boundary network fails a
strict `≤ 1` test either way. `is_reciprocal()` is `True` on benches A and C and `False` on B,
all three correct. **Nothing here is a defect in what ASE-L writes**, and it is recorded so the
next reader who runs `is_passive()` on a lossless bench does not re-derive it as one.

## 9. What is measured, and what is NOT

**Measured**: scikit-rf 2.1.0 only; Touchstone **v1** `.s2p` only; `RI` / `Hz` / `R 50` as
emitted, plus one forced `R 75`; 11 frequency points; 2-port and 3-port `sp` rows; both
binaries; parse, port count, point count, z0, frequency axis, S values, column order,
round trip, warnings.

**NOT measured, and no claim is made about any of it**:

* **No other reader.** ADS, Qucs/Qucsator, AWR, Keysight, `touchstone` in Octave — none was
  run, and none is installed here. "Valid to scikit-rf" is the claim; "valid to ADS" is not.
* **Touchstone v2 (`.ts`)** — `wrs2p` writes v1 and ASE-L asks for nothing else.
* **A noise-parameter block.** A `donoise 1` row was **not** put through `wrs2p` here, so
  whether the four noise scalars reach the `.s2p` (Touchstone v1 has a noise section) is
  **unmeasured**. It is the obvious next probe if anyone wants it.
* **1-port and 4-port files** — `wrs2p` is 2-port by construction.
* **Whether the S-parameters are physically right for the circuit.** Only that the file
  faithfully carries what ngspice computed.

## 11. What this binds

1. **Do not describe the `unlet Rbase` as protecting the Touchstone file.** It protects the
   `.raw`. The `.s2p` is byte-identical without it (§5).
2. **The `# Hz S RI R 50` line is the file's meaning, not its decoration.** Any future change
   to `sp_export_lines` that alters, reorders or drops it changes every number a consumer
   reads, silently (§7). `test_ase_sp_1452.tcl` row **SE1** already pins that literal.
3. **Any future test of S-parameter *values* needs a non-reciprocal bench**, or it cannot see
   the one defect the format invites (§4a).
4. **A 3-port row's `.s2p` is indistinguishable from a real 2-port**, so the caution in
   `sp_row_check` carries information that exists nowhere else (§6).
