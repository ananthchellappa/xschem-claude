## The design, and the one place ruling R1's wording does not survive contact

**A refusal by default; waiting is opt-in; neither ever destroys a verdict.**

```
T1_LOG_LOCK_WAIT   seconds to queue behind a live run before refusing. Default 0.
T1_LOG_LOCK_TTL    seconds after which a lock is broken even though something still
                   holds the owner's pid. Default 14400; 0 disables.
```

⚠ **R1 says "the second run waits, or refuses". WAITING ALONE DOES NOT CLOSE FACE 4, and
the row set proves it.** A run that queues politely and *then* opens the file mode `w`
destroys exactly the verdict the lock was taken to protect — the loss is merely orderly
instead of racy. Measured: with `T1_LOG_LOCK_WAIT=60`, run B waits for A, acquires, and
`results.log` ends up holding **0** of A's four case blocks. That is `V2b` red. So:

* **the default is to refuse**, which leaves A's verdict untouched and costs B nothing but
  a printed sentence;
* **the waiting path preserves**: before truncating, the verdict left by the run we queued
  behind is renamed to `results.<their-pid>.log` and announced. Measured: the preserved
  file is **13268 bytes with all 4 of A's blocks**, while B's own verdict occupies the
  canonical name. Nothing is lost on either branch.

`tests/*.log` in `.gitignore` already covers `results.<pid>.log` (verified on a real file).

⚠ **AND `file mkdir` IS NOT A LOCK IN TCL — the brief's precedent does not port.** The task
pointed at `tests/headless/gui_gate.sh:170`, an mkdir-based lock, which is atomic in
`/bin/sh` because `mkdir(2)` fails on an existing directory. **Tcl's `file mkdir` SUCCEEDS
silently on one** (measured, tcl 8.6.17: `rc=0`, no error), so the same shape here would
hand the lock to both runs and *read as correct in review*. The Tcl primitive with
`O_EXCL`'s guarantee is `open … {WRONLY CREAT EXCL}` (measured: second open `rc=1`,
`file already exists`), and that is what this uses. Everything else — the owner file, the
dead-owner break, the age backstop — follows gui_gate's shape faithfully.

**Breaking is on evidence, never on hope, and the evidence is better than a pid.** The
owner record is `{pid epoch script}`. A `kill -0` answers *yes* for a **recycled** pid,
which is how an age-only rule comes to break a healthy run's lock, so the owner's script
name is checked against `/proc/<pid>/cmdline`. This is also why the fixture works at all:
the suite's two driver copies are `drvA.tcl`/`drvB.tcl`, so any check hard-coding
`run_regression` would have failed to see a live holder and truncated anyway — green rows,
defect live.

**Fail-open, in four places.** The lock cannot become the reason T1 does not run: a lock
that can be neither taken nor broken after 4 attempts lets the run proceed **UNLOCKED**
with a warning; a garbled owner file is breakable; `$p == [pid]` is never "alive", so a run
cannot deadlock against itself; and on a box with no `/proc` it degrades to `kill -0` plus
the TTL. Single-run cost: **0.009 ms**, once per run, on the repo filesystem.

**A run that dies leaves the lock behind, deliberately** — there is no trap handler and
there should not be one. The next run breaks it on evidence and prints a NOTE.

## The alternative shape (`results.<pid>.log` + rename), costed from here

DECISIONS.md's third shape — every run writes `results.<pid>.log` and renames to
`results.log` at the end — is **now about 15 lines from where this ends up**, because the
preserve-on-wait arm already builds and exercises both halves it needs: per-pid verdict
naming and an atomic-enough rename onto the canonical name. Concretely: drop the acquire
and the refusal, open `results.<pid>.log` unconditionally at `:563`, and `file rename -force`
it onto `$log_fn` where the release now sits at `:732`. What it costs is what DECISIONS.md
already says and one thing it does not. Already recorded: the second finisher's rename still
overwrites the first's verdict, so one run's answer is still lost — cleanly rather than
truncated. **Not yet recorded: the suite's `V2b` would then red**, because `results.log`
ends up holding only the last finisher's blocks, exactly as measured on the waiting path
above. So the overturn is not merely an edit to this file; it retires or rekeys a row A1
wrote, and whoever takes it should expect to argue with `V2b` rather than be surprised by
it. The lock keeps **both** answers, which is the one thing the rename shape cannot do.

## Corrections to PLAN.md — V1 and D1 read this next

1. **⚠ D1: the acceptance sentence "second run waits or refuses loudly" is not enough, and
   the issue writeup must not repeat it.** Waiting and then truncating loses the first run's
   verdict just as surely as the race does. What shipped is: **refuse by default, wait only
   on `T1_LOG_LOCK_WAIT`, and preserve the previous verdict as `results.<pid>.log` before
   taking the name on the waiting path.** Prose that says only "it now takes a lock" describes
   something that would still fail the suite.

2. **⚠ V1: T1's behaviour on rc is no longer universally "exits 0 whatever happens".** A run
   that finds the tree locked exits **2** and writes nothing. That is deliberate — a refused
   run must not be mistakable for a pass — but CLAUDE.md's Tests section states the old
   invariant flatly, and D1 should correct that bullet along with the issue. Nothing in the
   tree reads the exit code (verified), so nothing breaks; the risk is a *reader*, not a
   caller. A normal solo T1 is unaffected: it takes the lock in 9 microseconds and exits as
   it always has.

3. **⚠ `V2a`'s DETAIL STRING now lies on the green path.** It is hard-coded to say *"and the
   second run announced nothing"* and prints the run's last line — which is now the closing
   `####...` banner. The row's *verdict* is correct (it passes because `_announced` matched);
   only its explanation reads as a red-state sentence. I did not touch it: it is A1's file
   and greening a row by editing its text is the thing this batch exists to prevent. It is a
   one-line wording fix for the driver or D1, and it will confuse the next reader until made.

4. **`V1a` is satisfiable by a comment.** It is a whole-file `regexp -nocase` for
   `lock|lockfile|\.lock\M|lock_file|…`, so any prose mentioning a lock greens it. It is a
   fine "the fix has not been reverted wholesale" sentinel and is **not** evidence the lock
   works — `V2a`/`V2b` are. Worth knowing before anyone cites V1a as the proof.

5. **The mkdir precedent does not port to Tcl** (see the design section). If a later crew
   locks anything else in a `.tcl` file, `file mkdir` is not the tool; `open … {WRONLY CREAT
   EXCL}` is. This is the single most likely way to reintroduce face 4 while every row stays
   green.

6. **For whoever takes 1232** (PLAN defers it because it edits this file): `hcases` is no
   longer one line — it spans `:27-93`, and `:94-113` is the new comment. The list is 69
   entries and every one resolves to a file on disk.

7. **PLAN's C1 row cites `~:295, :381`.** Post-B1 those lines are `:319` (`set log_fn`) and
