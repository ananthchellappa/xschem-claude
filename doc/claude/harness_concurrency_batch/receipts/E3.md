## The defect, and the two losing shapes

`ase::ui::bus_dialog` does `build` → `update` → `raise` → `grab set` → `focus` → `tkwait window`.
BB34/BB35 drove it with `after 100 {… invoke}` plus an `after 5000` deadman — byte-for-byte the
idiom 1332 was filed about, and **this file is where the keys suite copied it from.**

A probe inside the live modal settled the poll's condition by measurement rather than by argument:

```
PROBE obs=exists 1 grabcur .asebusbits grabwin .asebusbits focus .asebusbits.lf.list
```

`grab set`, `focus` and `tkwait` run with **no event loop between them**, so a driver that sees
`.asebusbits` holding the grab is running from inside `tkwait`. That is the poll's condition, and
the grab is compared to the **window**, never to `{}` (P3's SD8 lesson, adopted not re-learned).
