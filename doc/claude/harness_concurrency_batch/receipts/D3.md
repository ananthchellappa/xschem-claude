## Corrections to PLAN.md / the brief — the driver reads this next

1. **⚠ Residual 2's description is wrong in three places** — the D3 brief, `0905`'s closing
   section, and D1's correction 5 — and it will send the next reader hunting a writer that does
   not exist. *"A standalone suite run on `:99` … can still race those files"*: only
   `run_regression.tcl` writes `.disp.log`; `devdisplay.sh exec` does no redirection, the two
   shell drivers capture into variables, and `scratch.tcl` is already pid-qualified. 1478 opens
   with the correction and keeps 0905's underlying sighting, which is not in doubt — what that
   pair raced was the **display**, plus whichever of them was a regression run. **0905's
   closure should be amended**; I did not edit a closed issue that D1 had just written without
   the driver's say-so.
2. **⚠ `signal 15` is the wrong string to implement 0384 candidate 2 against.** Jobs end
   `; echo $? > '$status'`, so SIGTERM is recorded as **143**; `FATAL: signal N` comes from
   `src/main.c:58` into the case-log *body* and is read by `banner_died`. Two channels, one
   phrase. An implementer grepping for it in the job path finds nothing. In 1479.
3. **⚠ A constraint 0384 does not state, which the fix must respect: an `INFRA:` line must stay
   COUNTED.** Making it non-counting means a run where every job failed to start reports zero —
   exactly the fail-open `print_results` was hardened against in **0147**. `NOGOLD`/`NODISPLAY`
   are safe as non-counting only because they mean "no baseline", not "the thing under test did
   not run". This is the most likely way to "fix" 1479 and ship a quieter harness.
4. **0905's shape (3) needs two amendments it could not have known**, both derived from
   measurement, both in 1477: (a) with full buffering a START line is not evidence unless
   flushed, so the rule must be **"no END → HARNESS"**, never "START without END → HARNESS",
   which would score a 0-byte file as fine; (b) a run-level predicate in `banner_rule.tcl` is a
   **new** consumer, and that file is locked by `test_audit_classifier.tcl` section K — I have
   **not** verified section K tolerates an added proc, and said so rather than assuming.
5. **New fact worth keeping:** the verdict channel is full-buffered at **4096 B** while the whole
   verdict is **4785 B**. A killed run leaves 0 or 4096 bytes, not a proportional prefix — which
   is why 0905's original 0-byte sighting is the *typical* outcome, not an extreme one.
6. **`tests/results/` matches no `.gitignore` pattern at all.** It is invisible to `git status`
   only because every file inside happens to be named `Xschem.log*` (`.gitignore:30-31`). The
   day the display arm writes anything else there, it becomes untracked noise. Verified on real
   paths. Minor, recorded in 1478.
7. **I did not add back-references from the five closed issues to the new numbers.** 0905 and
   0955 mention their residual in prose; 0384 does too. Pointing them at 1477/1478/1479 by
   number would help the next reader, but editing five issue files D1 closed hours ago is a
   driver call, not a crew reflex. One-line edits if wanted.
8. **The brief's framing of residual 1 ("the lock makes this rarer") is right, and there is a
   sharper interaction worth having:** a killed run *deliberately* leaves its lock behind
   (`:724-732`), so the next run breaks it on evidence and truncates the fossil away. The window
   in which the short file is readable is exactly the window in which a person walks up and reads
   it. In 1477.
