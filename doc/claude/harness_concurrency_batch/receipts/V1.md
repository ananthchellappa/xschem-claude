## The three top-level cases, and a brief number that is wrong

```
results.log:2  NOGOLD: create_save … 10 result file(s) produced
results.log:5  NOGOLD: open_close  … 1898 result file(s) produced
results.log:8  NOGOLD: netlisting  … 1488 result file(s) produced
```

**All three are byte-identical to the pre-batch baseline log.** The batch changed none of
them.

⚠ **The brief's "the pre-batch counts were 10 / 1898 / ~1464–1472" is wrong for
netlisting, and the discrepancy is a category error rather than a regression.** The
baseline log says **1488**, this run says **1488**, and the on-disk tree holds **1468** —
because these are two different quantities:

* `print_results` prints `[llength $pathlist]` — the count of **planned** result files;
* `ls <case>/results | wc -l` counts the files that actually **landed**.

`netlisting.tcl` appends both `fn_debug` and `fn_netlist` to `pathlist` for every job that
is not FATAL, but only renames a netlist into `results/` `if {[file exists
"$workdir/$fn_netlist"]}`. Jobs exiting **10** — the *expected netlist error* path the
collate loop deliberately tolerates — therefore contribute a `pathlist` entry and no file.
That is the 1488 − 1468 = **20**. Both numbers are stable and neither indicates a defect.
**Report log against log**: 1488 → 1488, unchanged.
