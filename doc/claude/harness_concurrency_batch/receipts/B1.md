## The design choice, and its blast radius — for the driver, against ruling R1

**`results/` is now per-run.** Each case works in `<case>/results.<pid>`, computes its verdict
there, and then `publish_results` restores the canonical `<case>/results` name by
delete-then-rename. Scratch moved out of it entirely: `<case>/.work.<pid>`.

**Why not "keep `results/` shared and make only the wipe safe"** — the alternative constraint 2
offers, and which S2 would have accepted (it takes a `catch` on that line):

1. **It does not close face 2.** A guarded wipe still *fails*; the case then proceeds into a
   directory another run is writing. The suite is blunt about this: the D-section fixture copies
   only the **argument** of the wipe, and wraps it in its own `catch … exit 1`. D2a/D2b go green
   only when that argument is per-run. A `catch` in the case file greens the cheap S2 row and
   leaves the behavioural pair red — which is the row set doing exactly its job.
2. **It does not close the real defect either.** Two runs sharing `results/` cannot both produce
   a trustworthy verdict however the wipe behaves, because `print_results` would then compare
   `gold/$f` against a file the *other* run wrote. Guarding the wipe silences the crash and keeps
   the corruption.

**Blast radius, enumerated and all of it handled:**

* `print_results` takes an optional 4th arg (`{resdir {}}` → defaults to `$testname/results`), so
  any caller that does not have one behaves exactly as before. Both `$testname/results/$f` reads
  (`:165`, `:169`) follow it. All three callers pass `$resdir`.
* `netlisting.tcl:113`'s rename target, `create_save.tcl`'s two `results_dir` sites,
  `open_close.tcl`'s `$output` — all follow.
* **Gold promotion is unchanged**: `<case>/results/` exists under that exact name when the case
  ends, holding that run's files. Verified after every run below.
* **`.gitignore`** needed six new rules; verified by creating the directories (see the trap below).
* **The awk** needed the per-run token normalised out of result *content* (next section).

## The leak that forced the awk change — and it is the thing a reviewer should check hardest

The per-run token does not stay in the filesystem: **xschem prints these paths into the results.**
Measured on this tree, four shapes, all of which would otherwise differ **run to run on the same
machine with nothing changed** — a harder failure than the machine-absolute paths already in
there, since those at least compare equal to themselves:

| shape | files affected |
|---|---|
| `… set XSCHEM_TMP_DIR {<workroot>/44.tmp}` | **1898 of 1898** open_close, **5 of 10** create_save |
| `process_option(): file name given: <resdir>/simple_inv.sch` | 5 create_save |
| `is_from_web(<resdir>/simple_inv.sch) = 0`, `cli_opt_filename <resdir>/…` | 5 create_save |
| `.include <workroot>/251.d/model_test_ne555.txt` | **2 of 724** netlisting `.spice` |

The fix is two patterns that **map the token back to its canonical spelling** rather than blanking
the line (`results\.[0-9]+` → `results`, `\.work\.[0-9]+` → `.work`). Mapping, not `***Removed***`,
because it restores the exact text these lines had before the roots became per-run: the file keeps
its filename and context, an existing baseline still matches, and the recorded path agrees with
where `publish_results` finally puts the file.

The two netlist files needed one more thing: **only debug files were ever passed to the awk**, so
netlists were never normalised at all. `netlisting.tcl` now adds the published netlist to
`cleanlist`. Measured before doing it — a dry run of the awk over all 724 netlist files with the
existing pattern set changes **0 of 724**, so this costs nothing anywhere else. It also made
deduping `cleanup_debug_files` necessary: last-writer-wins renames can list one published path
twice, and two parallel awks rewriting one file is a corrupted file.

**Verification of the whole gold story:** `grep -rlE 'results\.[0-9]+|\.work\.[0-9]+'` over all
3376 result files → **0 files**. Two consecutive runs of each case → **byte-identical manifests**
for all three cases. That is the property gold needs, and it holds.

## Corrections to PLAN.md (and to A1) — C1 reads this next

1. **⚠ C1: the shape of `results/` HAS changed.** Cases now work in `<case>/results.<pid>` and
   publish to the canonical name at the end. `run_regression.tcl` needs **no** change for this —
   it never names a case's results dir — but C1 should not be surprised by the directories, and
   the `.gitignore` rules that cover them are part of this diff.

2. **⚠ A1's correction 4 is half wrong, and it changes C1's acceptance.** A1 reports face 4 as an
   erasure that always eats the **second** run, with `V2b` "green by design, non-vacuity". In 10
   runs here it was **9 of 10** that way — and in **run 8 the coin landed the other way**: `V2a`
   green, **`V2b` RED** (run A's verdict incomplete, run B's present). The face-4 race is
   symmetric: either run can be the one erased. So C1's acceptance must be *both* `V2a` **and**
   `V2b` green and **stable across repeats**, not "V2a flips and V2b was always green". A single
   post-fix run would not have caught this; neither would three.

3. **A comment can become the thing a source-text row measures.** Documented above. Any crew
   editing a line that a `has_text`/`src_line` row keys on must re-read the row's extractor
   first. This cost one full red/green cycle.

4. **PLAN's B1 file list is still short by two**: `tests/cleanup_debug_file.awk` and
   `.gitignore`. Both are forced by the per-run roots, not discretionary — without the awk the
   fix makes 1905 result files vary per run, which nothing in the suite can see and which would
   have shipped.

5. **Face 2 is fully deterministic once BOTH the results root and the workroot are per-run.**
   A1 measured "died at startup, 2 of 3" with only the workroot moved. With both moved it is
   10 of 10 clean. Nothing is shared between two runs of a case any more.

6. **Registration is still owed** (A1's note, updated): the suite is not in `hcases`, and
   `full_audit.sh:393` picks it up through its glob — so any full audit taken before C1 lands
   shows this suite **RED with 2 rows, by design**. That is two, not thirteen, and both are C1's.
