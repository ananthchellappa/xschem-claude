# V4 — a solo T1 and the first measured concurrent pair: the fix holds, but a pair still reds

**Status:** DONE

**Headline.** Seven full T1 runs. The R1-build fix **held on every axis it was built for**:
both concurrent runs proceeded, both verdicts are complete and self-identifying, neither lost
a block the other had, nobody was refused, and no run exited non-zero. **But one of the four
concurrent runs still produced a counted failure in the suite whose baseline is ZERO** — via
`/tmp`, a shared namespace the fix never scoped. So R4 relaxes *conditionally*, not now.

Three recorded numbers were re-measured and **two are wrong**: the brief's `wc -l` = **85** is
really **171**, and the "20% slower" figure is **backwards at full-T1 scale** — a concurrent
pair delivers both answers **~44% faster** than back-to-back, not 20% slower. The second of
those is printed to every crew by `run_regression.tcl` itself.

## ⚠ THE CONCURRENT RED: `W12b`, AND IT IS A REAL COLLISION THROUGH `/tmp`

Run B's failing case was `headless/test_suite_watchdog_1403`. **One row of 32:**

```
FAIL: W12b-no-emergency-save-corpse -- 37 -> 38 in /tmp; an external SIGTERM on this same hang adds one
RESULT: 1 FAILED (31 passed)
```

The mechanism, read from source rather than guessed
(`tests/headless/test_suite_watchdog_1403.tcl:265, :271, :275-277`):

```tcl
set em_before [llength [glob -nocomplain -directory /tmp -type d xschem_emergencysave_*]]
...
set em_after  [llength [glob -nocomplain -directory /tmp -type d xschem_emergencysave_*]]
check W12b-no-emergency-save-corpse [expr {$em_after == $em_before}] ...
```

* The glob is over **all of `/tmp`** — a global namespace.
* `src/main.c:42` names corpses `xschem_emergencysave_%s_` (schematic name + random suffix):
  **there is no pid in the name**, so the row cannot tell its own corpse from anyone else's.
* It compares **counts, not sets** — so *any* xschem dying anywhere on the box inside the
  window reds it. In a concurrent pair, the other run's deliberately-killed watchdog children
  do exactly that.

**This is the same defect class this batch already documented** for 0609's supplied fix code
("compares **counts, not sets**"), reproduced independently in a different suite.

**R1-build did not and could not cover this.** That fix scoped the verdict and the 83 per-case
logs under `tests/`. `/tmp/xschem_emergencysave_*` is a shared object **outside** R1-recon's
census of 88 — the census counted files under `tests/`.

**Confirmed not a standing red:** `test_suite_watchdog_1403` standalone → `RESULT: ALL PASS
(32 checks)`, rc 0, 18 s. It is green solo and in 6 of 7 T1 runs.

**Reported, not fixed** (this was a measuring task). Four other files glob the same name —
`scratch.tcl`, `test_zero_point_pos_at_0852.tcl`, `test_raw_read_failure_0306.tcl`,
`test_zero_point_raw_0836.tcl`. **I did not check whether those are count-based too**; they
should be triaged with W12b.

## ⚠ THE 20% FIGURE IS REFUTED AT FULL-T1 SCALE — AND THE HARNESS PRINTS IT TO EVERY CREW

R1-recon measured a single *case* pair at 20% slower concurrent than back-to-back
(64.4 s vs 53.7 s). **A full T1 pair behaves the opposite way.** I measured the back-to-back
baseline rather than deriving it from the solo run:

| mode | run 1 | run 2 | **time to BOTH answers** |
|---|---|---|---|
| **back-to-back** (solo, sequential) | 389 s | 382 s | **771 s** |
| **concurrent** pair 1 | 426 s | 430 s | **435 s** |
| **concurrent** pair 2 | 430 s | 431 s | **436 s** |
| solo reference (Part A) | 375 s | — | — |

* **To both answers: concurrent is ~44% FASTER** (435 s vs 771 s), not 20% slower.
* **Per run, concurrent costs ~12%** (426–431 s vs 382–389 s). That *is* directionally
  consistent with R1-recon — the sign flips only on the quantity the claim is about.
* **Why they differ:** this box has **20 cores** (`nproc`). R1-recon's `open_close` already
  fans out 16 parallel `xargs` workers, so a second copy is pure contention. A full T1 has
  long serial stretches, and two runs interleave into idle cores.

⚠ **`run_regression.tcl:665-666` prints this to every crew that starts a second run:**

```
  This is not faster: measured 20% SLOWER to both answers than running
  back-to-back. What it buys is that neither crew is turned away.
```

**The first sentence is measurably false for a full T1.** This is the batch's own **D2
"lying detail string"** class — a true measurement of one thing, printed as a claim about
another. Reported, not edited. *(The second sentence stands, and remains the real case.)*
