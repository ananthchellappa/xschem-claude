## What surprised me — read this first

**1. Nine of ten carry a rotted citation, and not one carries a bad fix.** The batch was
scoped around the harness batch's six prescribed fixes that would have damaged working
code (`BAD-FIX`) and its two files reporting done work as outstanding (`STALE-FIXED`). In
this decile the dominant defect is neither: it is **line-number rot**, 9/10, with
`BAD-FIX` and `STALE-OPEN` both at **zero**. If A2–A4 agree, **B1 and C1 are aimed at the
wrong target as currently framed in `PLAN.md`.**

**2. The answer to B1 is already inside the sample, measured.** `0071` is the only file of
the ten that cites **symbols and file paths and never a line number** — and it is the only
one of the ten with **zero** rotted citations. `0229` is the tracker's own write-up of
this exact defect; it prescribes *"Cite symbols, not offsets"*, supplies a ready-made
pre-commit grep, is **still OPEN**, and has itself rotted in the meantime. The corpus
diagnosed itself, prescribed the cure, and nobody applied it. B1's header convention
should require **a symbol plus a tree state**, never a bare line, and C1 has a
ready-written check to steal from `0229`'s "Prevention" block.

**3. `0229` has rotted by exactly the defect it files, including its own hero sentence.**
Its class-**d** entry — *"`select.c:790` … the only survivor"* — is now stale; the target
moved to `select.c:1021`. **An issue about line rot cannot state its findings in line
numbers.** Whatever C1 checks, it must be able to run against **an issue file**, not only
against source — otherwise the tracker's own meta-issues are the one thing it cannot see.

**4. The `1480`/`0609` failure is present but it is NOT in the header.** All ten status
lines are directionally right. `0071`'s header correctly says `OPEN`; the staleness is in
**§3, §4 and §4b** — a severity table that still lists `0063` as an unresolved HIGH while
`0063` reads `✅ REPLAYABLE`, a related-issues list calling `0003` "pre-existing" while
`0003` reads `CLOSED`, and a "Next mutators to convert" list of six items of which **five
are done**. ⚠ **A checker that validates only the opening block will score `0071` green.**
That is the single most important design input here: the rot lives *below the fold*, in
the tables an umbrella issue uses to track its children, and umbrella issues are exactly
the files people read to decide what to work on next.

**5. Nothing needed a suite, and one thing needed the binary for one second.** `NEEDS-RUN`
is empty. Nine were settled by reading source; `0435` by a single headless probe that
reproduced its filed table exactly. If that generalises, **C1's checker needs no
simulator, no display and no T1** — which makes "wired into the suites" cheap rather than
the hard part.

**6. Quoted code rots the same way line numbers do, and it rots invisibly (`0296`).** Two
of the ten quote C that no longer exists. A stale line number *looks* stale once you check
it; a stale quoted block still looks like valid C and reads as authoritative. `0296`'s
`sscanf(ptr, ".model %s %s", …)` was replaced by an offset-based parse when `model_name()`
grew a `keep_case` parameter — and that rewrite also made one of the issue's three
measured collapse rows **conditional on `netlist_case_mode()`** while the issue still
states it flatly. **No line-number checker catches this**, and it is the closest thing in
this decile to the `BAD-FIX` class: someone patching from that quote would be editing a
function that no longer has that shape.

**7. For stage D specifically — `0435` is a fix-by-reference that has quietly decayed.**
The prescription is *"a one-line `else` on the `< 'n'` branch **mirroring the `>= 'n'`
one**"*, and the issue quotes that mirror as `Tcl_SetResult(interp, "xschem set: invalid
command.", …); return TCL_ERROR;`. **That code no longer exists** —
`/usr/bin/grep -n 'xschem set: invalid command' src/scheduler.c` returns **nothing**; the
`>= 'n'` half now ends `else { *cmd_found = 0; }` (`:12982-12984`) and the message comes
from the top-level fall-through at `src/scheduler.c:15148`. Read as *"mirror it"* the
prescription is still correct. **Pasted, it introduces a second, divergent error path**
into a dispatcher whose whole point is one. I did not score this `BAD-FIX` — the
prescription is by reference and the reference still resolves — but D should apply it by
reading `:12982`, not by copying the issue.
