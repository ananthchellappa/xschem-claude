## 1. The dispatch brief's premise is wrong, and so is its prescribed method

Both are recorded here because the next crew reads this, and because this batch's subject is
issue files that prescribe fixes which would damage working work.

### 1a. "The collection step was skipped. Your task is to do it now."

**It was not skipped.** `R9_COPY_REVIEW.md` is 11 364 lines, **821 handle blocks**, **825
handle ids**, drawn from **38 issues**, grouped by *where the user sees the text* rather than
by issue number — which is precisely the standing label-ratification rule the brief quotes as
having been ignored. `DECISIONS.md:1030` of that batch states the rule being followed in as
many words: *"R9 is the exception to one-at-a-time, deliberately: it is BATCHED PER STAGE."*

What actually went wrong is narrower and worth stating precisely: **the collection was made
and then never handed over.** The debts kept being filed per stage *alongside* a document that
already contained them, so the queue grew while the review sat finished. The defect is a
missing handover, not a missing collection.

### 1b. "A `rule` entry is a pointer… Go get the real text" from the issue file

**Following this literally would have produced a document of superseded drafts.** The copy
review measured exactly this and says so at `R9_COPY_REVIEW.md:26-33` and
`ase_analyses_batch/DECISIONS.md:1505-1515`:

> **The issue files could not be the source.** Most of them only *describe* their copy
> (*"every label carries its unit"*, *"mints three frames"*, *"four precondition sentences
> with their four remedies"*), and several quote a draft that was superseded before the commit
> landed. Every string in the review was therefore taken from the **committed source at
> HEAD**… **A `rule` debt that records only a description does not preserve the sentence.**

I verified the shape of this directly: issue 1416's file describes *"the four field tables"*
and names no label; the review carries 25 labels from it verbatim. Issue 1439's file names its
sentences only by category; I had to read `src/ase.tcl` to get them.

**So I inverted the prescribed method:** for the 36 covered entries the review is the source;
for the 9 uncovered ones the issue file is, and where the issue file only describes, I went to
`src/ase.tcl`. Every string in the deliverable came from the shipped program or the review,
never from a description.

This is the same failure class `CREW_BRIEF.md:19-21` names — *"The sixth was written by the
driver, in a dispatch brief"* — arriving again in a dispatch brief, in the batch about it.

1. **First per-issue handle count was invalid.** My `awk` attributed **557** handles to issue

   `src/ase.tcl:24955-24997`, **indented inside a namespace block**, so the `^proc` anchor
   missed them. Corrected against the tree before it reached the deliverable — position, not
   identity, again.
4. **My own deliverable asserted a section it did not contain.** `RATIFY_WORDING.md` claimed 16
   questions and carried **15 headings** against **16** Q-numbers referenced: Q12 was cited in
   two tables and had no body. Found by `grep -c` on the artefact, not by re-reading my draft.
   Fixed; re-verified at 16/16 with an empty `comm -13`.

Errors 1, 2 and 4 are all the same defect — **counting a proxy instead of the thing** — which
