## 1. What I changed, by symbol

### `src/scheduler.c`

* **`getprop_gfx_prop()` — NEW static helper**, placed between `xschem_cmds_f()` and
  `xschem_cmds_g()`. Resolves `(type, layer_arg, index_arg)` to a layered graphic object's
  `prop_ptr`, or sets `*ok = 0` with an error in the interpreter for a layer/index out of
  range. One helper for all three types because they differ only in which `xctx` array and
  which count the pair addresses. Reads **only** `prop_ptr` — never `dash`/`fill`/`bus`,
  which are caches derived from it (and `xLine` has no `fill` at all).
* **`xschem_cmds_g()`, the `getprop` branch — new combined arm for `line` / `poly` / `arc`**,
  inserted between the `rect` and `text` arms. Grammar
  `getprop <type> <layer> <index> [token] [with_quotes]`; `with_quotes` is optional `argv[6]`
  defaulting to **0**, copying the `rect` arm (deliberately *not* `wire`/`text`'s hardcoded
  `2`). Arity floor `argc >= 5`. Bad layer/index → `TCL_ERROR`
  `xschem getprop: <type> not found: <c> <n>`.
* **`xschem_cmds_g()`, the `rect` arm — arity floor 6 → 5**, whole-string form added *below*
  the issue-0077 range check so both argument shapes are bounds-checked. Message now
  `xschem getprop rect needs <color> <n> [token] [with_quotes]`.
* **`xschem_cmds_g()`, the `text` arm — arity floor 5 → 4**, whole-string form added as the
  first branch, ahead of the `txt_ptr` / `size` pseudo-tokens. Message now
  `xschem getprop text needs <n> [token]`.
* **`xschem_cmds_g()`, the `wire` arm — arity floor 5 → 4**, whole-string form added below
  the 0077 range check. Message now `xschem getprop wire needs <n> [token]`.
* **The arm-list error string** (the `argc < 3` guard) extended to
  `xschem getprop needs instance|instance_pin|wire|symbol|text|rect|line|poly|arc`. A test
  row asserts all nine names are present, so it cannot silently become a lie again.
* **The `getprop` doc block** above the branch: the three new forms documented, the optional
  token recorded for rect/text/wire, `text`'s previously undocumented `size` pseudo-token
  written down, and a closing note that the attribute-omitted form is what makes
  `xschem list_tokens` work and that an unknown type name still returns empty (D6, filed not
  fixed).

No allocation was added anywhere, so no `_ALLOC_ID_` question arose. C89 verified
mechanically, not by eye: `gcc -fsyntax-only -std=c89 -pedantic -Wall

## 4. The sabotages

Eight variants, each built and run **in the isolated tree against the shipped 103-row fence**
so no other crew's edits could colour the result. `FINAL` at the end re-confirms the tree.

| # | the plausible wrong implementation | outcome | rows that caught it |
|---|---|---|---|
| **S1** | drop the layer/index range check in `getprop_gfx_prop()` and just subscript — the task's own named example | **`FATAL: signal 11`**, exit 1, no `OVERALL: ok` | the crash itself; `run_regression` scores a column-0 `FATAL` as FAIL. The 0077 OOB reproduced on the new path |
| **S2** | pass raw `prop_ptr` to `Tcl_SetResult(..., TCL_VOLATILE)` in all four whole-string sites, no `? :` NULL guard | **SURVIVED — `ALL PASS (103 checks)`** | none, and that is the correct answer: see below |
| **S3** | copy the old `rect` arity floor into the new arm (`argc < 6`), so the whole-string form never fires | 7 FAILED | the 3 `token omitted` rows, `prop-less line`, and all 3 `list_tokens` rows for line/poly/arc |
| **S4** | put `rect`'s whole-string branch **above** the issue-0077 range check | **`FATAL: signal 11`**, after first reddening a row | `1618 rect: an index equal to the live count raises, not just 999999`, then the crash |
| **S5** | copy-paste slip: `poly` and `arc` read `xctx->line[c][n]` | 6 FAILED | `token omitted` for poly/arc, both `token read comes from the … array` rows, both round-trip rows |
| **S6** | return the cached derived `dash` instead of the requested token (the task's second named example) | 12 FAILED | all 3 `token read comes from the … array`, all 3 round-trip, all 6 `with_quotes` rows |
| **S7** | hardcode `with_quotes = 2`, copying the `wire`/`text` arms instead of `rect` | 3 FAILED | the 3 `with_quotes=1 answers as the rect arm does` rows |
| **S9** | count mix-up: range-check every type against `xctx->rects[c]` | 3 FAILED | **only** the 3 `an index equal to the live count` rows — every `999999` row passed |

**Two of these changed the fence, and that is the point of running them.**

* **S5 would have survived my first draft.** The fixture gave line, poly and arc the *same*
  attribute string, so an arm reading the wrong array agreed with its sibling. Fixed by giving
  every type a distinct value (`aa=L` / `aa=P` / `aa=A` / `aa=R` / `aa=W` / `aa=T`) and adding
  three `token read comes from the <type> array, not a sibling's` rows. Found by planning the
  sabotage, not by the tests — which is the argument for the sabotage step existing.
* **S9 would have survived too.** Every out-of-range row used `999999`, which exceeds every
  count, so a check against the wrong count still rejected it. Fixed by adding five
  `an index equal to the live count raises, not just 999999` rows, read from the live counts.
  Layer 4 deliberately holds a different number of each type so the rows can discriminate.
* **S4's row was also missing** until I planned it: the 0077 rows only ever pass a token, so
  moving the guard below the new `argc` split left them all green. Seven
  `widened arm still range-checks with the token omitted` rows now cover that.

**S2 is reported as a non-defect, not as a fence gap.** With all four NULL guards removed and
four prop-less objects read, the suite stayed at `ALL PASS` with no signal 11:
`Tcl_SetResult(interp, NULL, TCL_VOLATILE)` tolerates a NULL string and answers `{}`, which is
why the shipped `instance` and `symbol` arms have always passed `prop_ptr` straight through. So
the two implementations are both correct. I kept the guards (they state the intent and do not
lean on an undocumented Tcl behaviour) and **corrected the test's own comment**, which had
claimed those four rows were NULL-deref crash fences. They are value rows. The comment now
says so, and says explicitly not to cite them as proof a missing guard would be caught.

## 5. D5's proof obligation — the census

**Result: ZERO callers depend on the token-omitted form erroring. The widening ships.**

**Instrument** (`<scratchpad>/B-impl/census.sh`), three layers, because a literal grep is not
a census — the thing it cannot see is a call whose *verb* is not a literal:

* **L1 literal** — `/usr/bin/grep -rnI -e 'getprop'` over `src`, `xschem_library`, `tools`,
  `utils`, `tests`.
* **L2 dynamic** — the `xschem` command invoked with a non-literal `argv[1]`. This is a
  **closed** syntactic set in Tcl (`xschem $v`, `xschem {*}…`, `xschem [...]`), so I detect
  *that* rather than trying to detect every way the seven characters could be assembled. Plus
  the C-side eval entry points.
* **L3 fragment** — `g`…`e`…`t`…`p`…`r`…`o`…`p` spelled with intervening punctuation on one
  line, and `get%s`.

**The instrument was validated against four deliberately evasive controls** before being
trusted (`<scratchpad>/B-impl/control2/`, comments stripped so only the call lines can match):

| control | spelling | caught by |
|---|---|---|
| A | `catch {xschem getprop rect 4 0}` with a failure branch — the exact dependency D5 asks about | L1 |
| B | `set v "get"; append v "prop"; xschem $v rect 4 0` | **L2 only** |
| C | `set cmdline [list getprop wire 3]; xschem {*}$cmdline` | L1 + L2 |
| D | C side, `my_snprintf(buf, …, "xschem get%s wire %d", "prop", 3); tcleval(buf)` | L2b + L3 |

Control **B is caught only by L2** — it is precisely the case a literal grep misses, which is
what makes the validation meaningful rather than decorative.

**Findings over the real roots** (code file types only: `*.tcl *.c *.h *.sh *.py *.awk *.sch
*.sym`):

* **1104 lines** containing `getprop` across **171 files**; **1194** `xschem getprop`
  adjacency occurrences.
* Type-word histogram: `rect` 741, `instance` 334, `wire` 86, `symbol` 34, `text` 13,
  `instance_notcl` 9, `instance_pin` 7. **No occurrence has a variable in the type slot.**
* **Token-omitted candidates for rect/text/wire: 12. All 12 inspected on their real source
  lines. All 12 are false positives** — 6 are comments or prose, 6 are my extractor stopping
  at a `(`, `[` or `"` (`getprop text $d(index) size`, `getprop rect 2 [xschem get
  graph_lastsel] node`, and the check *names* inside `test_getprop_index_bounds.tcl`'s own
  strings). **Zero real token-omitted call sites exist.**
* **L2: 51 dynamic-dispatch sites in code files.** Three can reach `getprop`:
  `tests/stable_handles/net_body.tcl`'s `gp {args}` forwarder (`return -2` on error — a real
  failure branch), whose 5 call sites **all pass a token**;
  `tests/headless/test_lib_browse.tcl`'s `q {args}` forwarder, which **never** calls
  `getprop`; and `tests/headless/fuzz/harness.tcl`'s `foreach v $verbs { xschem $v }`, whose
  verb list contains no `getprop` (its 8 real `getprop` calls all pass tokens).
* **L3: 1 hit**, a comment about "widget properties".
* **C side:** `getprop` appears in exactly **two** C files — `src/scheduler.c` (the
  dispatcher itself) and one comment in `src/callback.c` (which passes a token). Every C-side
  `av[1]` verb slot is a string literal; the only variable-verb sites
  (`log_action("xschem %s", verb)`, `log_action_argv`) are **logging**, not invocation.

**One more closure the census implies and I want on the record:** the widening keys on
**`argc`**, not on the token's content. A caller writing `xschem getprop rect $c $n $tok` with
`$tok` empty still supplies argc 6 and still takes the token path, byte-identically to before.
So there is no "empty variable silently becomes a whole-string read" hazard either.

## 6. What I got wrong during the stage

1. **I conflated "count before the call" with "index of the pre-existing object."** The first
   fixture read the prop-less rect and wire at the *count* index instead of 0, and two rows
   failed on the fixed binary with `{aa=1 bb=2} (exp {})`. Corrected by making the band create
   its **own** prop-less rect/wire/text rather than borrowing the 0077 fixture's, so it no
   longer depends on whether those two carry attributes.
2. **My `mk` fixture helper double-prefixed the command** (`xschem {*}$args` where `$args`
   already began with `xschem`), so **nothing was created** and eight rows went red at once.
   The fixture-assertion rows are what caught it and named it — which is the recon receipt's
   own lesson about the silently-uncreated arc, arriving one level up. Fixed with
   `uplevel 1 $args`.
3. **I claimed the prop-less rows were crash fences.** Sabotage S2 refuted it: Tcl tolerates a
   NULL result string. The comment is corrected and says not to trust those rows for that.
4. **I wrote a fixture whose types were indistinguishable**, which would have passed the
   array-mix-up sabotage. See §4.
5. **I did not notice for a long time that another crew was in the same tree.** I discovered it
   only when `git status` showed `tests/headless/test_wave_viewer.tcl` modified by someone
   else. By then I had already taken a red and a green through `make -C src` in the shared
   tree, and Stage A later added `src/callback.c`, `src/draw.c` and `src/xschem.h`. I re-took
   **both** figures in an isolated `git archive HEAD` build rather than report the mixed ones.
   One of my pristine-scheduler builds in the shared tree also failed to link
   (`undefined reference to vcd_read_set_end`) — a transient race with the other crew's
   concurrent `make`, not a defect in either change.
6. **I temporarily swapped `src/scheduler.c` to the pristine version and rebuilt the shared
   binary**, four times, to take reds and sabotages. Each was restored and rebuilt immediately,
   but **any suite the Stage A crew ran inside those windows saw a `getprop`-less binary.** I
   should have used the isolated tree from the start. Stated plainly because it could have
   produced a confusing red in their transcript.
